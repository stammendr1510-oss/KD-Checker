# Исполняемый репозиторий с областью org/project

`scoped_history.Repository.create(NEW_PATH)` создаёт отдельное хранилище схемы 1.
Существующий файл никогда не заменяется; нет пути к рабочей базе по умолчанию.
Это SQLite-реализация для синтетического стенда на локальном диске сервера,
не PostgreSQL и не общая SQLite на сетевой папке.

Все операции read/list/compare/save/update/history проверяют текущее членство
в транзакции и включают org/project в SQL. Составные FK запрещают ссылки между
проектами. Решение и audit event с actor, старым/новым состоянием, комментарием
и версиями фиксируются атомарно. Версия защищает от перезаписи; новые проверки
не наследуют решение. Предыдущий run выбирается только внутри той же области
и состава имён. Это связь истории, не доказательство редакции/исправления КД.

`provision/revoke/transaction` — доверенные административные методы, не HTTP API.
Actor передаётся только из будущей проверенной серверной сессии. Параметр
revision обязателен, но его подлинность должен подтвердить импортёр. Scope
не является удостоверением полномочий — членство проверяется отдельно.

Схема включена как версия начального создания. Обновляющие миграции пока не
реализованы, неизвестная версия отклоняется. Нет identity provider, passwords,
durable sessions, полноценного tenant-scoped config/document repository,
исторических Checklist snapshots, адаптера dispatch для PR #52 или staging
импорта legacy SQLite. Методы не заменяют storage.py и не переписывают его данные.

PostgreSQL не установлен/не проверен в этом запуске. Нельзя объявлять SQL
переносимым: AUTOINCREMENT, PRAGMA и блокировки SQLite требуют отдельного адаптера,
миграций и тестов PostgreSQL. Следующий пакет: интерфейс backend #52 → этот
репозиторий, полный бизнес-пайплайн, idempotent staging importer с manifest
org/project, сохранением legacy timestamps/ID mapping/audit, counts/digests/FK
и восстановлением на отдельном стенде. Рабочий Supabase не подключать.
