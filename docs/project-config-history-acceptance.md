# Регрессионная приёмка проектных настроек KD Checker

Зависит от Codex PR #68 и родителей; ветка основана на текущей #69, сохраняя его код без изменений. Собственные изменения — только тесты и документация.

Приёмочные проверки используют реальный защищённый HTTP, транзакционную `ProjectConfiguration` и отдельную синтетическую SQLite. Никаких рабочих конфигураций или реальных пользователей.

Проверяемые контракты:

- Отправка значения без изменений не увеличивает версию и не записывает фиктивное событие аудита (как до первого изменения, так и после него).
- В каждом проекте собственная цепочка версий, настроек и авторов; обновление проекта B не меняет проект A.
- Устаревшая `expected_version` возвращает 409 без частичной записи конфигурации или аудита.
- Понижение роли администратора до viewer после входа запрещает запись при сохранении возможности чтения.
- Строгая схема отклоняет неизвестные поля, отсутствующие значения, строковую версию и неоднозначные заголовки.

Команда: `python -m pytest -q tests/test_project_config_history_invariants.py`, затем общий CI Windows/Linux и совместный прогон с PR #58/61–69.

**Границы доказательства:** тесты не используют enterprise identity, не подтверждают TLS/reverse proxy, не выполняют эксплуатационное управление правами на нескольких физических компьютерах. `config.json` локальной версии не меняется. Нельзя объединять до родительских PR и ручной проверки diff.
