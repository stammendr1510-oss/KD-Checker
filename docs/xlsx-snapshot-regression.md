# Приёмка XLSX: сохранённые данные и недоверенный текст

Независимая регрессия для действующего `excel_reports.build_excel_report`, без изменения экспорта и без подключения к EPLAN Checklist/Supabase.

## Инварианты

- Выгрузка берётся из сохранённого запуска, а не из повторного чтения оригинальных PDF или облачного Checklist.
- Все пользовательские имена файлов, комментарии, сообщения, рекомендации, ссылки и текст исторического Checklist сохраняются как **строки**, включая значения, начинающиеся с `=`, `+`, `-`, `@`.
- XLSX не должен превращать такие значения в формулы.
- Для статусов `unavailable` и `not_configured` старые пункты Checklist не включаются в лист отчёта, даже если в некорректной синтетической записи они были переданы; выгрузка не изображает их актуальными.
- Статус и комментарий инженера отражают сохранённое решение.
- Запрещённые XML управляющие символы удаляются; переносы строк нормализуются.

## Что НЕ доказывает тест

Тест не доказывает безопасность любого офисного клиента, отсутствие внешних ссылок во всех возможных Excel-функциях и защищённость пользовательских компьютеров. Он проверяет именно генератор XLSX через `openpyxl` с синтетическим набором данных. CSV и PDF проверяются отдельными тестами. Не является проверкой промышленной эксплуатации.

## Выполнение

`python -m pytest -q tests/test_report_snapshot_safety.py`

После этого — общий CI Windows/Linux. Никакие работающие сервисы, файлы и учётные данные для тестирования не требуются.
