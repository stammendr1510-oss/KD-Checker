# Read-only диагностика базы долговременных сессий

Функция `quality.durable_session_preflight.inspect_durable_sessions(path)` проверяет структурную согласованность **доверенной остановленной копии** SQLite из PR #60. Её нельзя вызывать для публичного HTTP-запроса: это автономный внутренний инструмент контроля тестовой среды.

## Проверяемое

- `PRAGMA integrity_check` и `foreign_key_check`;
- точная поддерживаемая версия `session_schema = 1`;
- необходимые колонки таблицы `sessions`;
- хранение session/CSRF токенов в форме 64-символьных строчных SHA-256 hex digests;
- наличие привязки сессии к subject/org/project;
- допустимые конечные числовые сроки, положительный idle и `expires > last_seen`;
- общее число сохранившихся записей без раскрытия идентификаторов.

Возвращается только `{ok, problems, counts}`; диагностические сообщения ограничены 100 записями и не содержат токенов, хешей, субъектов, организаций и проектов. При неизвестной или повреждённой схеме ответ отрицательный. Отсутствующий файл не создаётся. Чтение идёт через SQLite `mode=ro` и `query_only=ON`.

## Границы

Это **не криптографическая проверка неизменности**, не восстановление сессий, не проверка безопасности конкретного логина и не гарантия того, что все token hashes уникальны за пределами ограничений самой SQLite. Истёкшие, но ещё не удалённые записи не считаются повреждением: время и политика очистки зависят от запуска приложения. Диагностика не сохраняет и не возвращает токены и не должна их использовать для аутентификации.

SQLite содержит потенциально чувствительные данные о членстве, поэтому анализировать следует только доверенную копию с локальными ACL. Нельзя публиковать саму базу, логировать её строки или тестировать на реальных учетных записях. Не заявлять enterprise-ready multi-PC session store на основании этого инструмента.

## Проверка

`python -m pytest -q tests/test_durable_session_preflight.py`

Синтетические сценарии обнаруживают повреждённые хеши, пустые scope-идентификаторы, некорректные временные поля, неизвестную версию и отсутствующую таблицу. Проверяют отсутствие побочных записей и невозможность случайно создать отсутствующую БД.

PR зависит от #60 и родителей. Для штатного CI используется временное сравнение с `main`, которое включает родительские файлы. До слияния #60 и его зависимостей не объединять этот PR. Дополнительных внешних библиотек или платных сервисов нет.
