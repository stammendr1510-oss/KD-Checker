# HTTP-матрица изоляции организаций и проектов KD Checker

Отдельный независимый пакет проверки защищённого API поверх PR #69/#68/#65. Ветка Codex, локальный MVP и основной runtime **не изменяются**.

## Сценарии

В одной временной SQLite одновременно существуют три независимых контекста: организация A / проект 1, организация A / проект 2 и организация C / проект 1. Последний специально использует **то же имя проекта**, что и в первой организации, чтобы исключить ошибочную изоляцию только по названию проекта.

С реальным защищённым FastAPI API проверяются:

- Информационные замечания KD-CON-101/102 создаются для синтетических JSON-соединений в каждом проекте и доступны только в своём scope.
- GET списка запусков, конкретного запуска, CSV, XLSX, истории решений и сравнения запусков скрывает чужие объекты одинаковым HTTP 404 независимо от того, принадлежит объект другому проекту той же организации или одноимённому проекту другой организации.
- Несовпадающая привязка finding ID к run ID не позволяет подделать решение, даже если указанный run принадлежит пользователю.
- Viewer может читать историю своего проекта, но не изменять замечания и не запускать импорт.
- Администратор меняет настройки только своего проекта; версия и история конфигурации не отображаются в других scope.
- Подмена поля project в структурированном JSON не создаёт частичные runs, decisions или audit events.

Все данные синтетические; настоящий verifier предприятия и реальные документы не применяются. Проверки проходят через реальный scoped backend, сессии, CSRF, маршруты и временный SQLite, а не через mock ответов.

## Ограничения доказательства

Матрица не подтверждает промышленную эксплуатацию на двух ПК, фактическую безопасность сетевого транспорта, PostgreSQL, TLS reverse proxy или подлинность native EPLAN экспорта. Описанные правила KD-CON-101/102 остаются **информационными**.

Порядок локальной проверки: `python -m pytest -q tests/test_tenant_scope_http_matrix.py`; затем единый Windows/Linux CI для готового PR. Ветка основана на PR #69, поэтому полный diff относительно main включает неслитые родительские коммиты. Нельзя объединять до ручной приёмки зависимостей.

## Ограничения расходов

Один штатный CI после готового кода; повторные запуски только при обнаруженной ошибке. Не включать платные runners и не изменять GitHub Billing. Лимит $5,16 был показан на прежнем скриншоте и не является текущим подтверждённым остатком.
