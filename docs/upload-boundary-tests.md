# Проверка границ загрузки

`tests/test_upload_boundaries.py` использует отдельную временную SQLite,
отключённый через stub источник Checklist и маленькие тестовые лимиты.
Рабочие лимиты приложения и настройки не изменяются.

Проверяются HTTP 413 для превышения размера файла, суммы размеров и числа
файлов, отсутствие частично сохранённой проверки после отказа, HTTP 200 на
точных границах. Искусственное исключение парсера не попадает в ответ,
сохранённую историю и CSV/XLSX: пользователю остаётся стандартное KD-000.

Это тесты контракта существующего API, не load test 100 МБ, не проверка лимитов
reverse proxy, multipart buffering или CPU/RAM парсеров. Они не доказывают
отсутствие всех возможных утечек в системе и не реализуют авторизацию.
Проверка повреждённых PDF и совместимости истории остаётся в существующих
синтетических тестах, включая test_acceptance_smoke.py.
