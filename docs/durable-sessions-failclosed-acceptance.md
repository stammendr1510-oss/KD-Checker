# Приёмка отказоустойчивости durable-сессий KD Checker

Независимая синтетическая матрица поверх PR #60. Не изменяет рабочую фабрику API, хранилище сессий или действующие данные.

## Проверяемые гарантии

- Создание базы сессий исключительно в новый файл; существующий файл и активная сессия сохраняются при отказе в повторном создании.
- Неизвестная версия схемы приводит к явному отказу, без тихой миграции.
- При исчерпании лимита сессий новая сессия отклоняется, предыдущая остаётся действительной.
- Некорректные токены не дают доступ и не отзывают чужую действительную сессию.
- Сессии разных пользователей/организаций различаются, отзыв виден другому экземпляру `DurableSessions`.
- В таблице сессий не сохраняются исходные session/CSRF tokens.
- Откат управляемых часов запрещает сессию без последующего «воскрешения».
- Точные границы idle и absolute timeout запрещают доступ.

Все идентичности синтетические. СУБД — временная server-local SQLite. Тесты ничего не знают о production verifier, TLS, shared PostgreSQL, реальных пользователях или многокомпьютерной эксплуатации.

Запуск: `python -m pytest -q tests/test_durable_sessions_failclosed.py`; затем полный CI Windows/Linux. Ветка основана на #60, а PR для стандартного CI нацелен на `main`; принимать только после зависимостей #44/#52/#55/#59/#60.
