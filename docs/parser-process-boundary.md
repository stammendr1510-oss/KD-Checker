# Отдельный процесс для обработки документов

Зависимости: #80 и его родители. В защищённом ScopedBackend check_documents
запускается через asyncio.to_thread → отдельный interpreter `python -I`.
Локальный app.py не меняется. Родитель не исполняет парсеры документов.

Вход: до 100 файлов, 20 МиБ каждый, 100 МиБ суммарно. Файлы с внутренними
безопасными именами и manifest лежат в приватном TemporaryDirectory, затем
удаляются. В child не передаётся исходное окружение: только PATH/SystemRoot,
WINDIR и локальные temp/home, число BLAS/OMP threads=1. Credentials не наследуются.
stdin/stdout/stderr не используются для данных или traceback.

Результат — ограниченный JSON-файл до 2 МиБ, ≤10000 стандартных findings;
проверяются размер, обычный файл без symlink, ключи, типы, уровни и коды.
Нет pickle/десериализации кода из child. Ошибки выводятся только как общий 503.
Deadline по умолчанию 20 с: зависший child принудительно завершается и ожидается
его выход. Сохранение run происходит только после принятого результата и новой
транзакционной проверки membership. При busy/timeout/некорректном результате
частичная проверка не сохраняется. Очередь не бесконечна: один worker на процесс
HTTP, остальные запросы получают 503. Это не глобальная квота нескольких workers.

POSIX: до импорта читателей применяются RLIMIT_AS (1 ГиБ), CPU (10 с),
FSIZE (2 МиБ), CORE=0 и NPROC=1. Числа конфигурируются только доверенным Limits,
не пользовательским HTTP. Проверены на Linux; NPROC не является защитой root.
Windows: Job Object с process-memory/CPU/active-process=1 и kill-on-close;
child ждёт bootstrap barrier до назначения job. Ошибка назначения запрещает
обработку, нет тихого fallback без job. Windows ветка реализована, но **не
проверена запуском** в этом окружении; обязательны Windows CI и стенд.

Это НЕ полная OS sandbox: нет ограничения сети/чтения файлов правами ОС,
контейнера, restricted identity или namespace. Парсер имеет права учётной записи
процесса. Нужен отдельный непривилегированный аккаунт и правила сети/ACL для
предприятия. Memory limit — виртуальная память на POSIX и committed memory на
Windows, эти свойства не эквивалентны. Global concurrency/temp disk quota,
корректная отмена при обрыве клиента и production supervision требуют работы.
Нельзя использовать на реальных КД или объявлять G1–G7 выполненными.

Тесты только synthetic: сохранение результатов четырёх форматов, hard timeout,
очистка temp, bounded result protocol, ENV redaction, busy refusal, HTTP без
частичного run, POSIX limits без изменения родителя. CI пропущен [skip ci]
при неизвестном остатке включённых Actions; это явно не Windows acceptance.
