## 1. Задача блока 2

Блок 1 показал, что `KD-PE-105` мог выдать `warning` и `confidence=high` для
семейства KM из 17 обозначений, сопоставив его со строкой ПЭ3, где количество
равно 1. Причина — смешение трёх разных сущностей:

1. точное наличие обозначения в раскрытых `entries`;
2. качество извлечения строки (`duplicate_eligible`);
3. смысловая принадлежность отсутствующего обозначения этой строке.

Блок 2 разделяет эти сущности. Совпадение буквенного префикса или семейства
больше не считается доказательством соответствия строки.

## 2. Извлечение обозначений и количества из ПЭ3

### 2.1. Явные разделители и переносы

[`_notation_parts()`](../kd_crosscheck.py:34) делит ячейку только по явным
разделителям `;` и `,`. Внутри фрагмента пробелы и переносы строк могут только
дополнять незавершённое обозначение или диапазон:

| Вход | Результат | Причина |
|---|---|---|
| `1TA1...1TA3` | `1TA1`, `1TA2`, `1TA3` | явный диапазон |
| `1TA1...\n1TA3` | `1TA1`, `1TA2`, `1TA3` | перенос дополняет диапазон |
| `3TA1\n...3TA3` | `3TA1`, `3TA2`, `3TA3` | перенос продолжает диапазон |
| `1TA1;1TA3` | `1TA1`, `1TA3` | явный список; `1TA2` не создаётся |
| `1TA1,1TA3` | `1TA1`, `1TA3` | запятая — разделитель списка |
| `XT1 2` | `unknown: ["XT1 2"]` | нет явного разделителя; нельзя выбрать `XT1` или `XT12` |
| `XT1\nXT2` | `unknown: ["XT1\nXT2"]` | две полные записи без разделителя неоднозначны |
| `1KM1...1KM3\n4` | `unknown` | продолжение не является диапазоном |

Правило намеренно консервативно: лучше сохранить неоднозначность, чем создать
несуществующее обозначение из числового пробела.

### 2.2. Количество

Количество извлекается существующим [`_quantity_words()`](../kd_crosscheck.py:96).
Оно **не порождает** обозначения. `quantity > len(entries)` — это свидетельство
того, что строка ПЭ3 неполная, но не доказательство того, что любое конкретное
отсутствующее обозначение принадлежит именно этой строке.

## 3. Модель доказательств

Для каждого отсутствующего компонента Э3 и каждой строки того же семейства
вычисляется класс доказательства
([`_row_match_evidence()`](../e3_pe3_inventory.py:350)):

| Класс | Условие | Использование |
|---|---|---|
| `exact` | обозначение или база контакта есть в `entries` | компонент считается найденным, замечания нет |
| `under_expanded` | `quantity > len(entries)` и группа совместима | единственная строка такого класса может дать warning |
| `family_group` | семейство и группа совпадают, избытка количества нет | предположительная привязка, только `info` |
| `family_only` | совпал только буквенный префикс, группа не совместима | не привязывается; `no_matching_pe3_row` |
| `none` | подходящих строк нет | `no_matching_pe3_row` |

Дополнительные ограничения:

- строка с `unknown` не может быть `under_expanded` или `family_group`;
- пустая группа обозначения совместима с любой строкой, конкретная группа — только
  со строкой, где есть обозначение той же группы;
- при нескольких строках одного класса строка не выбирается.

## 4. Алгоритм выбора строки

[`_attribute_component()`](../e3_pe3_inventory.py:405):

1. Собрать строки того же семейства, у которых есть `entries`.
2. Если ровно одна строка `under_expanded` — это подтверждённая строка,
   `reason=quantity_mismatch`.
3. Если строк `under_expanded` несколько — `row_ambiguous`, строка не выбрана.
4. Иначе, если ровно одна строка `family_group` — предположительная строка,
   `reason=row_matched_without_coverage`.
5. Если таких строк несколько — `row_ambiguous`, строка не выбрана.
6. Иначе — `no_matching_pe3_row`; `family_only` не привязывается.

`pe3_page` и `pe3_table_row` заполняются только для подтверждённой или
единственной предположительной строки. Для `row_ambiguous` и
`no_matching_pe3_row` они равны `null`.

## 5. Причины (`reason`) и их смысл

| `reason` | Значение | Severity |
|---|---|---|
| `quantity_mismatch` | уникальная строка с `quantity > len(entries)` и совместимой группой | warning возможен |
| `row_matched_without_coverage` | уникальная строка совпала по типу/группе, но покрытие не доказано | только info |
| `row_ambiguous` | несколько одинаково подходящих строк; выбор не выполнен | только info |
| `no_matching_pe3_row` | строка с подходящим типом не найдена | только info |
| `reference_only` | обозначения встречены только в ссылках/примечаниях | not_evaluated, info |
| `no_text_layer` | в Э3 нет текстового слоя | not_evaluated, info |
| `pe3_not_parsed` | обозначения ПЭ3 не извлечены | not_evaluated, info |
| `truncated` | обработка PDF ограничена | not_evaluated, info |
| `ambiguous_row` | устаревшая catch-all причина блока 1 | не формируется; новые результаты отклоняются валидатором |

Причина всегда пишется в `message` (`Причина: ...`), поэтому инженер видит
основание замечания без разбора JSON.

## 6. Достоверность (`confidence`)

[`_match_confidence()`](../e3_pe3_inventory.py:594) не зависит от severity:

- `high` — уникальная строка `under_expanded`, компоненты Э3 `high`/`medium`,
  анализ полный;
- `medium` — уникальная предположительная строка (`family_group`) либо строка
  не найдена;
- `low` — несколько кандидатов, только `family_only`, слабые доказательства Э3,
  `partial`/`truncated`.

`duplicate_eligible` остаётся признаком качества извлечения строки, но больше не
повышает `confidence` сам по себе.

## 7. Warning gate

Warning выдаётся только при одновременном выполнении:

- `reason=quantity_mismatch`;
- `evidence=under_expanded`;
- `quantity > len(entries)`;
- строка уникальна;
- `_row_confidence` строки `high`/`medium`;
- все компоненты Э3 `high`/`medium`;
- `confidence` `high`/`medium`;
- семейство не клеммное (`X`, `XT`, `XN`, `XL`, `XG`);
- нет `partial`/`truncated`.

Валидатор [`valid_details()`](../e3_pe3_inventory.py:830) дополнительно
отклоняет:

- warning с любой причиной, кроме `quantity_mismatch`;
- `row_ambiguous` с `confidence != low`;
- `row_ambiguous`/`no_matching_pe3_row` с заполненными `pe3_page` или
  `pe3_table_row`;
- `row_matched_without_coverage` с `confidence=high`;
- устаревшую причину `ambiguous_row`.

## 8. Контрольные случаи

### Случай A — TA

Э3: `3TA1`, `3TA2`, `3TA3`.
ПЭ3: `1TA1...1TA3; 2TA1...2TA3; 3TA1`, количество 9.

Результат: `quantity_mismatch`, `warning`, `confidence=high`, `missing=[3TA2, 3TA3]`.
Обозначения не додумываются по количеству: если в Э3 есть только `3TA2`, в
`missing` будет только `3TA2`.

### Случай B — KM

Э3: 17 обозначений `3KM2`…`3KM18`.
ПЭ3: одна строка `3KM1`, количество 1.

Результат: `row_matched_without_coverage`, `info`, `confidence=medium`,
`missing` содержит ровно 17 реально найденных обозначений. Warning невозможен,
`valid_details()` отклоняет попытку выставить warning.

### Случай C — одинаковые типы

Две строки ПЭ3 `3KM1` и `3KM2` с похожими наименованиями, отсутствует `3KM3`.

Результат: `row_ambiguous`, `info`, `confidence=low`, `pe3_page=null`,
`pe3_table_row=null`. Строки не объединяются и не выбирается произвольная.

### Ноль / одна / несколько строк

| Сценарий | `reason` | `pe3_page` |
|---|---|---|
| ноль подходящих строк | `no_matching_pe3_row` | `null` |
| одна подтверждённая строка | `quantity_mismatch` | заполнен |
| одна предположительная строка | `row_matched_without_coverage` | заполнен |
| несколько подтверждённых строк | `row_ambiguous` | `null` |
| несколько предположительных строк | `row_ambiguous` | `null` |

- Реальные PDF предприятия не добавлены в репозиторий.
