# KD-PE-106: достоверность диагностических результатов KD-PE-105

Дата: 22.11.2026. Аудит выполнен по коду `1d1b603` и по фактическим прогонам:
целевые тесты 162 passed, полный набор 1099 passed, синтетический стенд 8/8 PASS.
Реальные Э3/ПЭ3 не проверялись, поэтому калибровка на реальных данных
**NOT VERIFIED**.

## 1. Контракт уровней

| Уровень | Предусмотрен контрактом KD-PE-105 | Условие |
|---|---|---|
| `info` | да | всё, что не доказано как дефицит ПЭ3 |
| `warning` | да | уникальная строка, `quantity > entries`, полный анализ, не клеммное семейство |
| `error` | **нет** | ошибки обработки документов идут отдельным кодом `KD-000` |

Отсутствие `error` в KD-PE-105 — осознанное решение: непрочитанный документ не
должен выглядеть как инженерное несоответствие.

## 2. Как формируется confidence

`kd_pe_105_confidence.assess_finding()` собирает семь дискретных факторов
(`low < medium < high`) и берёт **минимум по обязательным**:

| Фактор | Что измеряет | `high` | `medium` | `low` |
|---|---|---|---|---|
| `e3_extraction` | качество извлечения обозначения | `label` | `split_label`/`reference` | слабое упоминание |
| `identifier_classification` | изделие или ссылка | `device_candidate` | `ambiguous` (потолок) | иная низкая уверенность |
| `pe3_extraction` | качество строки ПЭ3 | сетка + обозначения + количество | нет полосы строки | `unknown`, нет данных, одно обозначение при количестве > 1 |
| `row_match` | точность привязки | `under_expanded` | `family_group`, `no_matching_pe3_row` | `row_ambiguous` |
| `extraction_completeness` | полнота | нет `partial`/`truncated` | — | `partial`/`truncated` |
| `candidate_ambiguity` | единственность строки | уникальная подтверждённая | предположительная/нет строки | несколько кандидатов |
| `reason_constraint` | потолок таблицы решений | `quantity_mismatch` | `row_matched_without_coverage`, `no_matching_pe3_row` | `row_ambiguous`, `not_evaluated` |

Следствия, проверенные тестами:

- два `medium` не дают `high` (`test_two_medium_factors_never_produce_high`);
- `high` невозможен при `partial`/`truncated`, неоднозначной строке,
  отсутствии строки и при `row_matched_without_coverage`;
- количество одинаковых обозначений не повышает уверенность
  (`test_many_identical_designations_do_not_raise_no_matching_confidence`);
- `confidence` не выводится из `severity`: warning может быть `medium`
  (нет подтверждённой полосы строки), а info — `medium` или `low`.

**Важно:** `confidence` — эвристический уровень доказанности, а не
статистическая вероятность. Калибровка не проводилась, числовые проценты
в интерфейсе недопустимы.

## 3. Аудит по категориям результатов

| `reason` | Исходные данные | Основание | `info` | `warning` | Свидетельства | Риск ложного срабатывания | Риск пропуска |
|---|---|---|---|---|---|---|---|
| `quantity_mismatch` | строка ПЭ3, `entries`, `quantity`, сетка, Э3 | уникальная строка `under_expanded` и `quantity > len(entries)` | при `low`, `partial`, клеммном семействе | да, при `medium/high` | лист и строка ПЭ3, количество, число обозначений, список missing | средний: неверная привязка строки | низкий в пределах правила |
| `row_matched_without_coverage` | строка ПЭ3, семейство и группа | совпали тип и группа, покрытие не доказано | всегда | нет | лист/строка, число обозначений | низкий | средний: дефицит не подтверждается |
| `row_ambiguous` | несколько равных строк | выбор строки не выполняется | всегда | нет | список кандидатов, без листа/строки | низкий | средний: дефицит остаётся невыясненным |

| `ambiguous_row` | устаревшие записи | не формируется с блока 2 | чтение истории | запрещён | — | нет | нет |

## 4. Проверка требования «высокий confidence не из-за совпадения текста»

| Проверка | Результат |
|---|---|
| `high` требует всех обязательных `high` | да, правило минимума |
| количество обозначений не повышает уверенность | да, зафиксировано тестом |
| неоднозначная классификация ограничивает `medium` | да |
| `partial`/`truncated` дают `low` и запрещают warning | да |
| `high` невозможен при `no_matching_pe3_row` | да |
| warning без подтверждённой полосы строки | возможен, но `medium` (KD106-05) |

## 5. Проверка представления в интерфейсе

| Требование | Факт |
|---|---|
| уровень по-русски | «Ошибка», «Предупреждение», «Информация» |
| достоверность показана как уровень | да, без процентов |
| указан ограничивающий фактор | да, `explanation` |

| кандидаты строк при неоднозначности | да, в `message`/`location` |
| отсутствие координат PDF в человекочитаемом тексте | да, координаты только в JSON |
| переход к листу Э3/ПЭ3 | да, когда информация доступна |

Проверено фактическим прогоном группы «представление и экспорт»
(`test_kd_pe_105_evidence.py`, `test_excel_reports.py`,
`test_run_comparison.py`, `test_run_comparison_ui.py`, `test_issue_ui.py`,
`test_e3_pe3_details.py`): **73 passed, 1 warning, 12.84 s**, а также

## 6. Остаточные риски

1. **KD106-03 (P1):** семейства `K`, `KA`, `HL` не анализируются. Для реальной
   схемы это систематический пропуск, а не редкий край.
2. **KD106-02 (P2):** слово-маркер в одной строке с обозначением переводит его
   в ссылку и может скрыть дефицит ПЭ3.
3. **KD106-05 (P3):** warning при `medium` без подтверждённой строки. Контракт
   это допускает, но инженер должен видеть ограничение.
4. **Неполный разбор ПЭ3** (`unknown`, обрезанные строки) даёт `info`, а не
   warning: риск пропуска сохраняется и должен быть явно виден инженеру.
5. **Калибровка отсутствует:** сопоставление уровней с реальной частотой ошибок
   не выполнялось.

## 7. Вывод

Модель достоверности внутренне непротиворечива, консервативна и объяснима.
Она не превращает совпадение текста в доказательство и не позволяет
категоричному выводу появиться при неполном анализе. При этом достоверность
диагностики на реальных документах **не подтверждена**: для этого нужны
контрольные комплекты и протокол из
[`docs/kd-pe-106-windows11-test-plan.md`](kd-pe-106-windows11-test-plan.md).
