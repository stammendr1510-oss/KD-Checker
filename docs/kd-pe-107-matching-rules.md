# KD-PE-107: правила сопоставления обозначений Э3 и ПЭ3

Дата: 23.11.2026. Документ описывает **общие условия** правил, введённых в
KD-PE-107. Ни одно правило не привязано к конкретному коду изделия, имени файла
или номеру листа; `TA2/TA3`, `KLD3`, `SO1/S01` — только контрольные примеры.

Обозначения: `TAG` — общая структура позиционного обозначения
`[группа][семейство][номер][.вывод]`; `RANGE` — диапазон обозначений.

## 1. Семейства обозначений (`TAG_PREFIX`)

[`kd_crosscheck.py`](../kd_crosscheck.py) распознаёт семейства:

```text
HLG, HLW, HL, KLD, KM, KK, KV, KT, KA, KL, K, QF, SF, TA, SB,
XG, XT, XN, XL, X, PAV
```

Условие: обозначение целиком соответствует `TAG` после нормализации
(кириллица → латиница, верхний регистр, без пробелов). Групповой префикс —
1–2 цифры.

Следствия:

- `K1`, `KA1`, `KL1`, `HL1`, `KLD1` — кандидаты в изделия;
- одиночные `X1` остаются `ambiguous` (клеммник неоднозначен);
- `XT4.2`, `1KM1:A1` — вывод/контакт, не отдельное изделие;
- токен вне `TAG` сохраняется как `ambiguous` с причиной `non_tag_token`,
  а не отбрасывается.

## 2. Раскрытие групповой ячейки ПЭ3

Функции: `_notation_parts()`, `_split_single_line()`, `expand_notation()`.

### 2.1. Разделители

| Вход | Условие | Результат |
|---|---|---|
| `TA2;TA3` | `;` | два обозначения |
| `QF1,QF2` | `,` | два обозначения |
| `TA2`⏎`TA3` | перенос между двумя **полными** | два обозначения |
| `1TA1...`⏎`1TA3` | перенос внутри незавершённого диапазона | диапазон `1TA1…1TA3` |
| `KLD1...KLD3` | диапазон с однозначными границами | `KLD1,KLD2,KLD3` |
| `XT1`⏎`2` | полное + нечисловой/неполный токен | `ambiguous`, сохраняется `\n` |
| `TA2 2` | полное + токен на одной строке | `ambiguous` |
| `1TA3...1TA1`, `1TA1...2TA3`, `> 100` | обратный/смешанный/длинный диапазон | `ambiguous` |

Правило не «додумывает» границы: если диапазон нельзя раскрыть однозначно,
он сохраняется как неоднозначный фрагмент.

### 2.2. Колонка обозначений

`_designator_column(page, words)`:

1. ищет заголовок `поз`, `обознач…`, `позиц…` в верхней части листа;
2. по вертикальным линиям/рамкам находит границы колонки вокруг заголовка;
3. принимает границы, только если ширина 10 pt … 35 % листа;
4. иначе использует границы текста заголовка;
5. при отсутствии заголовка — исторический fallback 9–18.8 % ширины.

`_row_rules()` привязывает горизонтальные линии строк к найденной колонке.
Это устраняет пропуск сгруппированной строки, когда колонка шире прежнего окна.

### 2.3. Присутствие в текстовом слое ПЭ3

`pe3_text_designations(pdf_bytes)` возвращает обозначения из текста ПЭ3.
`compare_inventories(..., pe3_text_designations=...)`:

- обозначение в `missing`, но найденное в тексте ПЭ3 → исключается из `missing`;
- формируется `not_evaluated` с причиной `present_in_unparsed_pe3_text`;
- вывод: «строка не разобрана», а не «изделие отсутствует».

Это разделяет **ошибку извлечения** и **инженерный вывод**.

## 3. Конфликт повторного обозначения (KD-PE-106)

Модуль [`designation_conflicts.py`](../designation_conflicts.py), функция
`compare_names(left, right)`.

### 3.1. Условие конфликта

Повтор обозначения — не ошибка. Warning выдаётся только если одновременно:

1. обозначение встречается в ≥ 2 строках с подтверждённой сеткой
   (`row_band[0] ≥ 50`);
2. наименования изделий различаются;
3. найдено явное несовместимое свойство:
   - **напряжение**: оба имени содержат номинальное напряжение, и множества
     не пересекаются (`24VDC` vs `230VAC`);
   - **тип**: оба имени содержат тип изделия с цифрой, и множества не
     пересекаются (`KPR-SCE-24VDC-1C` vs `KPR-SCE-230VAC-1C`).

### 3.2. Матрица результатов

| Сравнение | Результат | Вывод |
|---|---|---|
| одинаковые наименования (без пунктуации/регистра) | `compatible` | нет замечания |
| разные напряжения | `voltage_conflict` | `KD-PE-106` warning |
| разные типы | `type_conflict` | `KD-PE-106` warning |
| различаются, явного атрибута нет | `ambiguous` | `KD-PE-106` info |
| одно имя недоступно | `unknown` | нет замечания |
| клеммное семейство `X/XT/XN/XL/XG` | — | warning не выдаётся |

### 3.3. Ограничения доказательства

- строки без `row_band` не используются;
- область заголовка (`band[0] < 50`) не считается строкой изделия;
- показываются первые 4 строки (`MAX_EVIDENCE_ROWS`), не более 20 замечаний
  (`MAX_FINDINGS`);
- правильный вариант не выбирается, строки не изменяются.

Совместимый повтор дополнительно отражается `KD-PE-104` уровня `info`
(в `duplicate_findings`), чтобы факт повтора был виден без ложного warning.

## 4. Похожие символы (KD-PE-107)

Модуль [`confusable_designations.py`](../confusable_designations.py).

### 4.1. Модельный токен

Условия `_is_model_token()`:

- 2–8 сегментов через точку, ни один не пустой;
- есть хотя бы одна цифра и хотя бы одна буква;
- длина ≤ 64;
- не документный код вида `ТНБВ.666666.666`.

### 4.2. Условие кандидата

Пара `(E3, PE3)` даёт кандидата, если:

1. длины токенов равны и токены не равны;
2. различается **ровно одна** позиция;
3. символы этой позиции входят в известную пару:
   `O/0`, `I/1`, `S/5`, `B/8`, `А/A`, `С/C`, `К/K`, `Е/E`, `М/M`, `Н/H`,
   `Р/P`, `Т/T`, `Х/X`, `У/Y`;
4. пара не является чисто кириллица/латиница (это `KD-PE-103`);
5. оба написания не присутствуют с обеих сторон одновременно.

### 4.3. Уровень

Только `info`. Текст явно сообщает: «кандидат на опечатку, а не подтверждённая
ошибка», символы не заменяются. Не более 5 кандидатов (`MAX_CANDIDATES`).

## 5. Свойство обозначения и роль появления

Функции: `_reference_role()` в [`e3_pe3_inventory.py`](../e3_pe3_inventory.py),
`_is_cross_reference()` в
[`identifier_classification.py`](../identifier_classification.py).

### 5.1. Когда маркер меняет роль

| Расположение маркера | Роль |
|---|---|
| непосредственно перед токеном (`см. QF1`) | `cross_reference` |
| документная ссылка в строке (`ТНБВ.666666.666`) | `cross_reference` |
| строка начинается с `прим…` | `note` |
| маркер в заголовке/далеко от токена | роль **не** меняется |

Окно близости — ±24 символа вокруг токена. Маркер `лист`, `табл`, `примечание`
в заголовке столбца больше не скрывает изделие.

### 5.2. Маршрутизация вывода

| Категория компонента | Результат |
|---|---|
| `TERMINAL_OR_PIN`, `CONNECTION_REFERENCE`, `CROSS_REFERENCE` | `reference_only`, не missing |
| только `reference/note/table/unknown` | `ambiguous` |
| `confidence == "low"` | `ambiguous` |
| `DEVICE_CANDIDATE` с достаточной достоверностью | проверяется на missing |

Свойство обозначения сохраняется в `category`/`classification_reason`
независимо от роли появления.

## 6. Усечение контекста

`_clean(value, limit, mark_truncation=True)`:

- удаляет управляющие символы и нормализует пробелы;
- при `len > limit` возвращает `text[:limit-1] + "…"`;
- лимит контекста — 300 символов, лимит имени ПЭ3 — 300 символов;
- усечённый контекст остаётся валидным для `valid_details()` и не выглядит
  полным.

## 7. Матрица независимых комбинаций

Проверяется, что правило не зависит от конкретного семейства и типа.

| Семейство | Групповая запись | Конфликт | Похожие символы |
|---|---|---|---|
| `TA` | `TA2;TA3` | — | — |
| `QF` | `QF1,QF2` | `QF1` 24VDC/230VAC | `QF1`/`QFl` (не пара) |
| `KM` | `KM1...KM3` | `KM1` тип A/тип B | `KM1`/`KMl` (не пара) |
| `KLD` | `KLD1...KLD3` | `KLD3` 24VDC/230VAC | `KLD1`/`KLDl` (не пара) |
| `KA` | `KA1,KA2` | `KA1` тип A/тип B | — |
| `KL` | `KL1;KL2` | `KL1` тип A/тип B | — |
| `HL` | `HL1,HL2` | `HL1` 24VDC/230VAC | — |
| `X/XT` | `XT1...XT4` | warning не выдаётся | — |
| модель | — | — | `SO1.PLC.01`/`S01.PLC.01` |
| модель | — | — | `DI1`/`D11`, `ABC.123`/`ABC.128` |

## 8. Пограничные и отрицательные случаи

| Случай | Ожидание |
|---|---|
| `TA2 2` (пробел) | `ambiguous`, не `TA2`/`TA22` |
| `XT1`⏎`2` | `ambiguous` с сохранением `\n` |
| `1TA1...1TA103` | `ambiguous`, диапазон не раскрыт |
| два разных семейства в одной ячейке | не объединяются в один диапазон |
| повтор без сетки | не доказательство конфликта |
| заголовок таблицы | не строка изделия |
| оба написания с обеих сторон | не кандидат `KD-PE-107` |
| документный код | не модельный токен |
| одинаковые имена | не конфликт |
| клеммная сборка | не warning |
