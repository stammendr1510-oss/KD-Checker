# Read-only диагностика истории проектных настроек

`quality/project_config_audit_verifier.py` добавляет функцию `inspect_project_config_history(PATH)` для доверенной **остановленной копии** локальной SQLite (версия scoped schema 1, после внедрения PR #68).

## Контроль

- Проверка `PRAGMA integrity_check`, `foreign_key_check` и версии схемы.
- Непрерывная цепочка `old_version/new_version` с 0 до текущей версии.
- Совпадение `old_payload` с исходным baseline или предыдущим `new_payload`.
- Совпадение текущих project_config payload/version с последним событием.
- Отказ считать нулевую версию нестандартной конфигурации без истории подтверждённой.
- Отсутствие фиктивных событий при неизменённых настройках.
- Отсутствие пустого автора, времени и осиротевших событий.
- Независимый подсчёт по всем проектам; ограничение количества диагностических сообщений.

## Безопасность и границы доказательства

Функция работает через SQLite URI `mode=ro` и `PRAGMA query_only=ON`, без изменений файлов и без HTTP-маршрута. Возвращает только количество конфигураций/событий и коды проблем — **не** настройки, имена акторов и секреты.

Это не криптографическое подтверждение истории: администратор с записью во все таблицы способен согласованно подделать цепочку. Это также не production-миграция, не восстановление бэкапа, не многокомпьютерная приёмка и не оценка ГОСТ. Для неизвестных версий схемы — fail-closed.

Поддерживаются только конфигурации, созданные известной схемой PR #68; baseline из `config.json` должен соответствовать тому, с которым создавалась история. При обновлении baseline на новой версии приложения старые исторические записи требуют отдельного проверенного порядка миграции, иначе могут справедливо отмечаться как непроверенные.

## Тестирование

`python -m pytest -q tests/test_project_config_audit_verifier.py`

Синтетические сценарии намеренно разрывают цепочки, меняют payload, версии, автора, удаляют текущую конфигурацию, вставляют фиктивные события и проверяют отказ неизвестной схемы без ремонта повреждённых данных.

Ветка основана на `feature/secure-body-budget` (PR #69), включая его зависимости; родительские PR должны быть приняты до ручного слияния этого пакета. Новые изменения — только автономный диагностический модуль, тесты и эта документация. Никаких обращений к Supabase, EPLAN Checklist, платным AI API или реальным данным.
