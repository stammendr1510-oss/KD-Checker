# Регрессионная матрица базового движка KD Checker

Тест `tests/test_engine_rule_boundary_matrix.py` закрепляет существующее поведение чистого `engine.analyze` без чтения реальных документов, сетевых запросов и SQLite.

## Проверяемые области

- Имена и обозначения: включение/отключение KD-001; контроль существующего шаблона.
- PDF: точная граница минимального числа символов KD-002; информационная классификация ограничений KD-005.
- DXF/DWG: независимость KD-003 от KD-004 и сохранение статуса отсутствующей поддержки DWG.
- Спецификация: обязательные заголовки KD-010, локальная область повторных позиций KD-011, эвристические ссылки KD-012.
- Дубли: различие форматов и повторы в одинаковом формате KD-020.
- Контракт каждого результата: уровень, документ, место, код, описание и рекомендация.
- Неизменность входных объектов при выполнении `analyze`.

Каждый случай строится с помощью `extractors.Document` в памяти. Набор не утверждает соответствие ЕСКД/ГОСТ, электрическую топологию, правильность графики и полноту комплекта. Отдельные правила Э3↔ПЭ3, СП и соединений тестируются в других модулях.

## Запуск и приёмка

`python -m pytest -q tests/test_engine_rule_boundary_matrix.py`

После выполнения целевых тестов требуется полный набор на Windows/Linux CI. Изменения в проекте Codex следует оценивать по причине каждого отклонения, а не автоматически ослаблять тесты для зелёного CI.

Это отдельная ветка без изменений runtime, настроек и реальных данных.
