# Состав загруженного комплекта ВО / Э3 / ПЭ3 / СП

Реализация Issue #14 находится в независимом `full_set_completeness.py`.
Она не использует Checklist, Supabase, сеть или внешние AI. В `app.py` добавлен
отдельный вызов для успешно прочитанных PDF; прежние пайплайны пар, проверки,
история, статусы и выгрузки не переписаны. Миграция SQLite не требуется.

## Распознавание и область

Чистая функция `classify_pdf_name(name)` возвращает неизменяемый `PdfIdentity`
(`kind`, `key`, `designation`) либо `None`. Требуются расширение PDF и ровно одно
явное обозначение с кодом `.ВО`, `.Э3`, `.ПЭ3` или `.СП`. Поддержаны смешанный
регистр, Unicode NFC, Windows-пути, пробелы вокруг точек и составные имена с
описанием после кода. Поддерживаемая база: 2–12 букв кириллицы/латиницы и 2–6
числовых групп длиной от двух цифр. Пример: `ABCD.123456.001.СП synthetic.pdf`.
Ключ — база обозначения без кода типа, с приведением регистра и удалением пробелов
вокруг точек. Описание файла не включается в ключ.

Два обозначения, два кода, неполная база, неявный тип, латинские подстановки кода
и неподдерживаемая нумерация дают `None`. База без `.СП` не считается спецификацией
по умолчанию. Похожие буквы разных алфавитов не приравниваются. Одинаковые базы
разных проектов без отдельного идентификатора проекта неразличимы: группировка
показывает только совпадение имён, а не общую принадлежность выпуску или редакции.
Существующие `designation_type()` и `pair_key()` не изменены.

`upload_inventory(names)` даёт группы всех распознанных четырёх типов и список
нераспознанных имён. HTTP-замечания полного комплекта включаются только для групп,
где присутствует ВО или СП. Набор только Э3/ПЭ3 остаётся в прежних KD-SET-101/102/103,
чтобы не дублировать привычную сводку. При полном контексте информационные сообщения
о совпадении типа/ключа могут сосуществовать с прежним контролем PDF-пар.

## Новые информационные коды

- **KD-SET-201**: число загруженных PDF и присутствующие известные типы по ключу;
  нераспознанные PDF указаны отдельно. Число файлов не равно числу самостоятельных
  редакций или полноте проекта. Даже все четыре типа не дают заключения о выпуске.
- **KD-SET-202**: несколько загруженных файлов одного типа и ключа, включая
  повторную загрузку одного имени. Это могут быть копии или разные редакции;
  содержание не объявляется ошибочным. Коллизий с кодами 101–103 нет.
- **KD-SET-203**: документ явно перечислен в СП, но не включён в текущую загрузку
  среди распознанных PDF. Указаны файл СП, страница PDF, строка таблицы,
  столбец и точная извлечённая запись. Отсутствие в выпущенной КД не утверждается.

Нет априорного правила, что каждый выпуск обязан содержать все четыре типа.
Без доказательства из СП отсутствующие файлы вообще не перечисляются.
Только данные текущего запроса задают наличие; старая история не является
доказательством присутствия PDF в новой загрузке.

## Что читается из СП

Поддержан узкий проверяемый случай: единственный заголовок «Обозначение», столбец
с вертикальными и горизонтальными границами, заданными линиями PDF, и один
полностью помещающийся в ячейке физический текстовый ряд. Содержимое ячейки должно
целиком совпасть с обозначением документа. Помимо четырёх типов допускаются
явные `.ПС` и `.РЭ` как ссылки и как имена загруженных целевых PDF; они не
становятся пятым/шестым типом основной сводки.

Обычное упоминание в тексте, примечание, перенос ячейки, обрезание, неизвестный
код, двойной заголовок, несколько обозначений в ячейке, отсутствие сетки или
ненадёжное чтение дают пропуск. Проверяются не более первых 100 страниц СП.
Порядковая строка считается по горизонтальным линиям, включая заголовок;
номер страницы PDF не объявляется номером листа основной надписи.

Несколько СП одного ключа блокируют чтение ожиданий из этих версий. Нераспознанный
или нечитаемый PDF во всей загрузке блокирует сообщения о недостающих ссылках:
это может оказаться искомый файл. Ошибка чтения СП не превращается в вывод об
отсутствии документов. Эти ограничения намеренно допускают пропуски ради
снижения ложных выводов. Общая сводка загрузки при этом остаётся доступной.

## Контекст другого вида документа с тем же базовым обозначением

Если в достоверной ячейке СП назван документ конкретного вида, но в текущей
загрузке нет PDF именно этого вида, информационное сообщение KD-SET-203 может
дополнительно перечислить распознанные документы с **тем же базовым
обозначением, но другими видами** (например, СП указывает Э3, а загружен ПЭ3).
Это только подсказка для ручной сверки и не означает подмену, ошибочную
классификацию или отсутствие выпущенной документации.

Наличие точно указанного документа подавляет KD-SET-203 независимо от иных
типов с тем же ключом. При неизвестных или нечитаемых PDF пропуск сообщений
о недостающих ссылках сохраняется: такие файлы могут быть требуемыми.
Похожие латинские/кириллические буквы не приравниваются автоматически.

## «Листов» против количества страниц: только дизайн

Эвристика **не реализована**. Простой поиск слова «Листов» и числа недопустим:
в PDF могут быть несколько рамок, частичный экспорт, включённые приложения,
отдельные тома, текст из примечания или отличающаяся нумерация. Их различие с
числом страниц не доказывает ошибку основной надписи.

Для будущей реализации нужны: подтверждённая область основной надписи известного
шаблона; единственное поле общего числа листов; проверка соответствия всех рамок
одному документу и экспорту; исключение неполных выгрузок/приложений. При любом
конфликте проверка должна пропускаться. Даже уверенное отличие — максимум
информационный повод проверить экспорт, а не подтверждённая инженерная ошибка.

## Проверка и границы изменения

Регрессии используют только программно созданные PDF, включая кириллический
текст. Проверяются все четыре типа, неизвестные/неоднозначные имена, группы и
дубли, ссылки ПС/РЭ, точные источники СП, отрицательные случаи, неполная загрузка,
нечитаемые файлы, страницы, API, история, комментарий, XLSX и CSV. Прежние тесты
инженерных правил и Checklist выполняются без изменения их исходников.

`checklist_run.py`, `checklist_snapshot.py`, интеграционные файлы и тесты Checklist,
рабочий сайт и локальная Windows-установка не изменяются. В репозиторий не входят
реальные документы, фрагменты или координатные выгрузки предприятия.
