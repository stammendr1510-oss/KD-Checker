# Неизменяемое происхождение запуска (изолированный стенд)

Защищённый backend сохраняет снимок **фактически выбранной** конфигурации и её
версии перед запуском worker. Изменение настроек администратором во время
обработки применяется к следующему запуску. Новый run, начальные решения и снимок
сохраняются одной транзакцией с повторной проверкой членства. Ошибка сохранения
снимка откатывает весь run. Решения предыдущего запуска не переносятся.

Снимок v1 содержит pipeline, эффективные настройки, версию настроек, лимиты
parser process, локальный SHA-256 исходных файлов и версии Python/runtime
зависимостей. Для JSON-соединений настройки документов и parser limits явно
`null`: они не участвовали в этой проверке. Пароли, токены, cookies, переменные
окружения и содержимое документов в снимок не включаются. Снимок ограничен 16 KiB.

Аддитивная таблица `run_provenance` создаётся внутри транзакции первой записи.
Составной внешний ключ привязывает её к org/project/run; UPDATE/DELETE запрещены
триггерами. Это не защита от владельца файла SQLite. Старые базы без таблицы и
старые строки без снимка читаются как `unknown/not_recorded`, без записи и
подстановки сегодняшних настроек. Повреждённый сохранённый снимок вызывает общий
безопасный отказ HTTP 503, а не подменяется неизвестным. Структурная схема чтения
v1 фиксирована: старые regex остаются инертными строками и никогда не компилируются
при чтении, не проверяются по текущему списку разрешённых regex.

Fingerprint исходных файлов и runtime-зависимости фиксируются при создании
backend, проверяются до/после обработки. Изменение файлов на работающем стенде
запрещает сохранение нового запуска; нужен обычный перезапуск. Это локальные
сведения о файлах, **не аттестация загруженного кода**, не lockfile и не доказательство
корректности проверки или соответствия ГОСТ. Не обновлять код на работающем сервере.

HTTP чтение, история, экспорт и сравнение используют прежнюю серверную изоляцию.
Сравнение отдельно показывает равенство настроек/исходников/runtime; при неизвестном
прошлом возвращает `null`. Интерфейс объясняет неизвестность. XLSX защищённого
запуска добавляет лист «Происхождение» с безопасными строковыми ячейками. CSV не
меняет колонки. Экспорт локального MVP без поля provenance сохраняет старые листы.

`synthetic_stand.py accept --synthetic-only --workspace NEW_DIR` проверяет
сохранение снимка и его сохранность после backup/restore. Синтетические тесты
проверяют реальную гонку admin config/HTTP upload/worker, атомарный rollback,
неизменность, tenant isolation, legacy unknown, corruption refusal и XLSX formula
safety. Staging-регрессия выполняется в совместном прогоне с #56; отдельно она
явно пропускается при отсутствии staging_import. Реальные данные не мигрируются.

Windows/CI и два Windows ПК требуют отдельного запуска в доступной бесплатной
квоте. Production identity, PostgreSQL, OS sandbox и эксплуатационная приёмка
остаются внешними gates. Этот блок не делает стенд производственной системой.
