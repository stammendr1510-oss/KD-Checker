# Проектные настройки и аудит

Зависимости: #65 и его родители. PUT /api/config принимает только
{expected_version: integer, settings: полный Settings}. Без версии — 409
(совместимость со старым неподключённым write), неверная схема — 422,
устаревшая версия — 409. GET сохраняет прежний JSON настроек; версия в
X-Config-Version. GET /api/config/history возвращает audit только своего проекта.

Администратор проверяется повторно внутри BEGIN IMMEDIATE. Настройки, версия
и событие actor/time/old/new фиксируются в одной транзакции. No-op не создаёт
новую версию, но требует текущую expected_version. Viewer читает настройки и
историю; engineer/viewer не пишут. config.json никогда не меняется.

Поддержаны все существующие переключатели, порог текста PDF и заголовки.
Произвольный designation_pattern пока запрещён: без bounded regex он может
блокировать общий процесс. Разрешён только baseline-шаблон. Настройки по умолчанию
считываются из config.json при импорте модуля и действуют до первой явной записи
проекта; для production нужен единый версионированный baseline всех workers.

Добавочные таблица событий и столбец version создаются только в scoped-базе
стенда, без миграции local history. Нет PostgreSQL и production cutover.
Тесты #61/#62 не изменялись; PUT {} по-прежнему отклоняется 409 без записи.
