# Отрицательная интеграционная приёмка защищённых HTTP-операций

Зависит от PR #44 → #52 → #55 → #59 → #60; ветка основана на `feature/durable-test-sessions` и не меняет исходники этих PR.

Синтетический тест `tests/test_secure_http_adversarial_contracts.py` использует настоящий `ScopedBackend`, `Repository`, HTTPS TestClient и изолированную SQLite во временной директории. Не используется backend spy или действующий сервис.

## Что проверено тестовыми сценариями

- Неподдерживаемый формат загрузки, отсутствующая или пустая редакция и лишние поля multipart приводят к отказу до создания run, decisions и audit.
- Подмена идентичности через заголовки `X-User-Id`, `X-Role`, `X-Organization-Id`, `X-Project-Id` отклоняется.
- Неизвестные методы и пути не приводят к побочным записям.
- Viewer не может менять конфигурацию; даже admin получает явный 409 для пока неподключённого изменения, без фиктивного успеха.
- Сохранённые значения с префиксами формул = + - @ остаются инертными строками XLSX и экранируются в CSV.

Эта проверка не заменяет стресс-тесты гигабайтных загрузок, изоляцию обработки по CPU/RAM, production HTTP reverse proxy или сертификацию ГОСТ. Ни реальных документов, ни живого Supabase, ни EPLAN Checklist, ни платных сервисов не требуется.

## Запуск

`python -m pytest -q tests/test_secure_http_adversarial_contracts.py`

Затем необходимо подтвердить полный CI Windows/Linux, после принятия зависимостей перезапустить тесты на обновлённом `main`. Без явного решения владельца не объединять PR.
