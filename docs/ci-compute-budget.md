# Экономия GitHub Actions без снижения покрытия

В workflow Tests добавлена `concurrency` для каждого номера PR с `cancel-in-progress: true`. При новом коммите в **тот же** PR старый незавершённый workflow отменяется, но другие PR не затрагиваются. Последний коммит по-прежнему получает полный pytest, Playwright и обе ОС (`ubuntu-latest`, `windows-latest`).

## Что этот механизм не делает

- Не уменьшает число job для последнего коммита и не удаляет Windows-тесты.
- Не останавливает старый запуск до момента, когда GitHub обработает новый workflow; уже потреблённое вычислительное время не возвращается.
- Не отменяет CI другого PR, даже если ветки связаны зависимостями.
- Не гарантирует нулевой биллинг; остаток включённого бюджета должен проверяться в GitHub Billing отдельно.
- Не подменяет жёсткий GitHub billing budget и не меняет финансовые настройки аккаунта.

Изменение только CI, без доступа к секретам. Работоспособность механизма отмены можно подтвердить при двух быстрых обновлениях **одного** PR, но ради экономии квоты специально генерировать такие дополнительные workflow-запуски не нужно.

После ручного review и разрешённого слияния правило начнёт применяться к следующим PR. До слияния режим на действующем `main` остаётся прежним.
