# Регрессии исторических сравнений KD Checker и EPLAN Checklist

Независимый синтетический набор тестов проверяет, что историческое сопоставление не выдаёт неполные данные за актуальную инженерную проверку и не изменяет прошлые решения.

## Критерии

- Для EPLAN Checklist сравнение доступно только при `verified` для **обоих** исторических снимков; статус `unavailable` или `not_configured` не разрешает подставлять старые пункты.
- При достоверных снимках сравниваются семь исходных полей требования, а результаты добавления, удаления и изменения воспроизводимы и отсортированы по ID.
- Сопоставление возвращает независимые копии данных; пользователь результата не может мутировать сохранённый исторический снимок.
- Сравнение КД не переносит решения инженера на новый запуск и не изменяет входные данные.
- Изменившаяся кратность файлов не считается тем же набором.
- Неоднозначные идентичные замечания остаются неоднозначными, а не превращаются в фиктивное одно-к-одному сопоставление.

## Границы доказательства

Тесты не выполняют запросов к живому Supabase, не подтверждают соответствие требований EPLAN КД, не проверяют реальные документы, идентичность пользователей, RLS или авторизацию серверного API. Они относятся только к чистым функциям `compare_checklist_snapshots` и `compare_runs`.

Команда: `python -m pytest -q tests/test_historical_comparison_invariants.py`.

После неё обязательно проверить общий CI Windows/Linux перед ручным решением о слиянии. Не подменять отсутствующие данные историческим cache fallback.
