# KD-PE-105: схема структурированных доказательств `details` v1

## Назначение

Поле `details` добавлено только к замечаниям `KD-PE-105`. Оно хранит машинно-читаемые доказательства, чтобы не дублировать полный список обозначений в `message` и не менять формат остальных правил.

Обязательные поля замечания остаются прежними:

`severity`, `code`, `file`, `location`, `message`, `recommendation`.

`details` — аддитивное необязательное поле. Замечания `KD-PE-100`–`KD-PE-104` его не содержат.

## Схема v1

```json
{
  "schema_version": 1,
  "kind": "e3_pe3_missing_designations",
  "status": "evaluated",
  "reason": "quantity_mismatch",
  "e3_document": "ТНБВ.656451.162.Э3.pdf",
  "pe3_document": "ТНБВ.656451.162.ПЭ3.pdf",
  "e3_pages": [1, 2],
  "pe3_page": 2,
  "pe3_table_row": 5,
  "pe3_row_band_pt": [70.0, 130.0],
  "pe3_page_size_pt": [600.0, 800.0],
  "pe3_quantity": 9,
  "pe3_entries_count": 7,
  "pe3_name": "Трансформатор тока измерительный ТТК-А-40/5А-5ВА-0,5S-УХЛ3",
  "pe3_name_confidence": "medium",
  "pe3_source": "1TA1...1TA3; 2TA1...2TA3; 3TA1",
  "type_family": "TA",
  "type_name": "трансформатор тока",
  "confidence": "high",
  "partial": false,
  "truncated": false,
  "missing": [
    {
      "designation": "3TA2",
      "raw": "3TA2",
      "pages": [1, 2],
      "kinds": ["label", "reference"],
      "evidence": [
        {
          "page": 1,
          "kind": "label",
          "context": "3TA2",
          "bbox_pt": [60.0, 90.0, 78.0, 96.0],
          "page_size_pt": [600.0, 800.0]
        },
        {"page": 2, "kind": "reference", "context": "3TA2:И1 - 3X1:3"}
      ]
    }
  ],
  "ambiguous": [],
  "limits": {
    "max_pages": 100,
    "max_listed": 1000,
    "truncated_list": false
  }
}
```

## Поля

| Поле | Смысл |
|---|---|
| `schema_version` | Версия схемы; сейчас `1` |
| `kind` | Всегда `e3_pe3_missing_designations` |
| `status` | `evaluated` или `not_evaluated` |
| `reason` | Причина: `quantity_mismatch`, `reference_only`, `no_text_layer`, `pe3_not_parsed`, `truncated`, `no_matching_pe3_row`, `row_matched_without_coverage`, `row_ambiguous`; `ambiguous_row` сохранён только для чтения старых данных |
| `e3_document`, `pe3_document` | Имена исходных PDF |
| `e3_pages` | Листы PDF Э3, где найдены доказательства |
| `pe3_page`, `pe3_table_row` | Лист и, при достоверной сетке, строка таблицы ПЭ3 |
| `pe3_row_band_pt` | Вертикальные границы строки ПЭ3 в PDF-пунктах, если известны |
| `pe3_page_size_pt` | Размер страницы ПЭ3 в PDF-пунктах, если известны координаты |
| `pe3_quantity` | Количество из строки ПЭ3 |
| `pe3_entries_count` | Число раскрытых позиционных обозначений |
| `pe3_name` | Наименование позиции ПЭ3, best-effort |
| `pe3_name_confidence` | `high`, `medium`, `low` |
| `pe3_source` | Исходная запись диапазона из ПЭ3 |
| `type_family`, `type_name` | Семейство обозначений и его пояснение |
| `confidence` | Итоговая достоверность по единой модели блока 4 (минимум обязательных доказательств) |
| `partial`, `truncated` | Ограничение обработки PDF |
| `missing` | Подтверждённые отсутствующие обозначения |
| `ambiguous` | Ссылочные/неоднозначные обозначения, не ставшие warning; причина элемента — `reference_only` или `needs_context` |
| `limits` | Применённые границы и признак усечения списка |

## Координаты

`bbox_pt` и `page_size_pt` необязательны. Если координаты переданы:

- все числа конечные;
- `0 <= x0 < x1 <= width`;
- `0 <= y0 < y1 <= height`;
- `pe3_row_band_pt` лежит внутри `pe3_page_size_pt`.

Некорректные координаты отклоняются валидатором worker, а не исправляются молча.

## Модель достоверности (блок 4)

`confidence`, `severity`, `reason`, `status`, `partial` и `truncated`
формируются единой моделью
[`kd_pe_105_confidence.py`](../kd_pe_105_confidence.py). Схема v1 при этом не
расширяется: набор ключей и `schema_version=1` остаются прежними.

Итоговая достоверность — минимум по обязательным доказательствам:

- качество извлечения Э3;
- уверенность классификации обозначения;
- качество извлечения строки ПЭ3;
- точность соответствия строки;
- полнота извлечения (`partial`/`truncated`);
- неоднозначность кандидатов;
- ограничение выбранной причины.

`high` невозможно при неполном анализе, неоднозначной строке, отсутствии
строки или слабом извлечении. Количество одинаковых обозначений не повышает
достоверность при `no_matching_pe3_row`. Полная таблица решений и инварианты —
[`docs/kd-pe-105-confidence-model.md`](kd-pe-105-confidence-model.md).

## Ограничения

- `missing` — до 1000 элементов;
- `ambiguous` — до 100;
- `evidence` — до 3 на обозначение;
- `pages` — до 10 на обозначение;
- `e3_pages` — до 100;
- документы — до 1000 символов;
- наименование, источник и контекст — до 300 символов;
- общий размер `details` — до 256 КиБ.

При превышении `missing` усекается, `limits.truncated_list=true`, а `message` сообщает, что полный список ограничен.

## Валидация в parser worker

[`parser_process._validate_result`](../parser_process.py:102):

- `KD-PE-105` обязан иметь `details` и не может иметь `evidence`;
- `KD-PE-100` может иметь `evidence` только в result_version 2;
- остальные коды не могут иметь ни `details`, ни `evidence`;
- [`valid_details()`](../e3_pe3_inventory.py) проверяет ключи, типы, границы, координаты, документы из `known_files`, типы `.Э3`/`.ПЭ3`, `pair_key`, `issue['file'] == details['pe3_document']` и согласованность `severity`/`status`.

## Excel

Основной лист `Замечания` сохраняет 10 базовых колонок. Если хотя бы у одного замечания есть `details`, после колонки J добавляются:

- `Доказательства KD-PE-105` — человекочитаемое доказательство: обнаруженные обозначения, документы и листы Э3/ПЭ3, подтверждённая строка, характер расхождения, причина достоверности, чего не хватило, кандидаты и рекомендации;
- `Детали KD-PE-105 (JSON)` — компактный JSON schema v1.

Для запусков без `details` формат листа не меняется. Отдельные листы на каждое замечание не создаются. Все значения записываются как текст, поэтому формулы Excel не исполняются. Человекочитаемый текст не содержит координат PDF; они остаются только в JSON.

## CSV

CSV всегда остаётся строго с шестью существующими колонками:

`Важность`, `Код`, `Файл`, `Место`, `Замечание`, `Рекомендация`.

Структурированные доказательства в CSV не выводятся. Человекочитаемые описание и рекомендация остаются в `message` и `recommendation`, включая первые 10 обозначений.

## История и API

- SQLite-схема не меняется; `details` хранится внутри JSON замечания.
- Старые записи читаются без миграции.
- [`issue_tracking.finding_identity()`](../issue_tracking.py:23) добавляет канонический JSON `details` только при его наличии. Замечания без `details` сохраняют прежний fingerprint.
- Сравнение проверок, решения инженера и журнал изменений работают с новым замечанием как с обычным.

## Инженерное представление (блок 5)

`details` schema v1 остаётся единственным сохранённым источником. На чтении
формируется `evidence_view` ([`kd_pe_105_evidence.py`](../kd_pe_105_evidence.py))
и не записывается в SQLite. Он не меняет fingerprint, решения инженера и журнал
изменений. Подробное описание:
[`docs/kd-pe-105-evidence-presentation.md`](kd-pe-105-evidence-presentation.md).

## Интерфейс

Локальный интерфейс и secure workbench показывают блок «Структурированные сведения»:

- обнаруженные обозначения и их полное число;
- документы и листы Э3/ПЭ3;
- лист и только подтверждённую строку ПЭ3;
- количество и число раскрытых обозначений;
- наименование ПЭ3;
- тип и классификацию результата: изделие, контакт/клемма/ссылка или
  неопределённый случай;
- характер расхождения и пояснение;
- достоверность и причину достоверности;
- чего не хватило для достоверного вывода;
- кандидатов ПЭ3, если автоматический выбор строки невозможен;
- рекомендации инженеру;
- отсутствующие обозначения с листами и контекстами;
- неоднозначные обозначения;
- причину `not_evaluated`.

Если номер строки таблицы не подтверждён сеткой PDF, интерфейс пишет «строка
таблицы не подтверждена» и не показывает координаты. Строки-кандидаты
добавляются производителем в `message`/`location` (`Кандидаты ПЭ3: ...`), так
как схема v1 не расширяется.

Краткий перечень в UI ограничен 50 обозначениями, блок доказательств — 200;
полный список — в Excel. Это защита DOM, а не потеря данных.
