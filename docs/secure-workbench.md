# Русскоязычное рабочее место защищённого стенда

Зависимости: #69 и его родители. `/workbench`, `/workbench.js`, `/workbench.css`
отдают только фиксированные статические файлы без данных и доступны до входа.
Для них допустимо только GET с пустым телом. CSP разрешает только свои script,
style и connect; нет inline handlers/eval, внешних assets, фреймов и localStorage.
`/auth/context` требует действующую сессию и текущее членство. Все операции КД
по-прежнему проходят серверные роли, scope, CSRF и транзакционную авторизацию.

Вход — тестовое доказательство для переданного verifier, не пароль предприятия.
UI не включает verifier и не создаёт пользователей. Есть upload, импорт JSON
соединений, список запусков, фильтры важности/статуса/кода/документа, решения,
комментарии, аудит, сравнение и CSV/XLSX. Строки документов и комментариев
попадают в DOM только через textContent/value. 401/403 очищают рабочее место;
счётчик поколения сессии отклоняет поздние ответы старой сессии.

CSRF живёт только в памяти страницы. После reload сохранённая cookie даёт чтение,
для записи нужен повторный вход с ротацией. Смена проекта/выбор membership и
production identity provider пока не реализованы: проект привязан к сессии.
PDF не сохраняется и навигация по исходному PDF не обещается. Настройки проекта
пока управляются через API, не через этот UI. Local static/index.html не меняется.

Браузерная приёмка: Playwright Chromium → in-process HTTPS ASGI transport →
настоящий ScopedBackend/SQLite. API не подменяется готовыми ответами. Проверены
вход, upload, фильтры, запись/аудит, повтор, сравнение, download, 360px, защита
DOM, viewer и чужой проект. Это не тест настоящего TLS handshake; TLS verification
не отключается, listener в LAN не запускается.

При неизвестном остатке включённого Actions commit помечен [skip ci]. CI и
фактическая приёмка на двух Windows ПК остаются обязательными перед выпуском.
Не объявлять этот интерфейс production-ready и не развёртывать автоматически.
