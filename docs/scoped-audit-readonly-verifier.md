# Read-only проверка целостности журнала scoped-хранилища

Модуль `quality/scoped_audit_verifier.py` реализует отдельную диагностическую функцию `inspect_scoped_history(path)`. Он **не исправляет** записи, не переключает рабочую базу, не подключает PostgreSQL и не предоставляет HTTP API.

## Для чего предназначен

Перед приёмкой восстановленной локальной **остановленной копии** SQLite можно проверить:

- `PRAGMA integrity_check` и `foreign_key_check`;
- точную версию `schema_version=1`;
- непрерывность версий событий для каждого org/project/run/ordinal;
- соответствие исходных и конечных статусов/комментариев соседних событий;
- соответствие текущего решения последнему событию аудита;
- наличие автора и времени в каждой записи;
- наличие решения для каждого события;
- общее количество runs, decisions и events.

Функция работает в SQLite read-only `mode=ro` и `PRAGMA query_only=ON`, возвращает `{ok, problems, counts}`; число сообщений о проблемах ограничено. Отсутствующий файл, неподдерживаемая схема или повреждение приводят к отказу, а не к фиктивному успеху.

## Ограничения доверия

Эта диагностика **не является криптографическим доказательством неизменности**: обладатель права записи может одновременно подделать решение и всю цепочку аудита. Она также не обнаруживает все виды удаления целых запусков, не подтверждает нормативное соответствие КД, не проверяет физические диски или резервную политику предприятия. Запускать на доверенной остановленной копии, не на живой базе с конкурентными писателями.

Не использовать как единственный критерий принятия production backup. Нет замены реального восстановления в тестовую среду.

## Синтетические регрессии

`python -m pytest -q tests/test_scoped_audit_verifier.py`

Тесты намеренно искажают временные базы, подтверждают обнаружение разрыва цепочки, расхождений версий, отсутствующего автора, нарушенного FK и новой версии схемы. Продуктовый `scoped_history.py` не меняется.

Ветка основана на PR #55 и не затрагивает его исходники. Если PR временно нацелен на `main` для Windows/Linux GitHub Actions, его diff включает родительский #55. Ручной приём сначала #55, затем этой диагностики.
