# KD-SET-103 — неоднозначное сопоставление Э3 ↔ ПЭ3

Если при одной загрузке присутствует несколько **разных по байтам PDF** одного
типа и одного ключа обозначения, автоматический выбор пары для проверки Э3 ↔ ПЭ3
не является надёжным. Правило `KD-SET-103` выдаёт одно сообщение уровня
`info` на группу, для которой присутствуют оба типа документов, но
неоднозначен хотя бы один из них.

В такой группе автоматическая сверка `KD-PE-100/101/102/105` пропускается.
Инженеру предлагается выбрать по одному PDF Э3 и ПЭ3 подходящей редакции
и выполнить проверку заново.

## Что продолжает работать

- Однозначные пары других обозначений проверяются как прежде.
- Несвязанные ПЭ3 продолжают проверяться на повторяющиеся позиционные
  обозначения `KD-PE-104` даже при наличии нескольких редакций в загрузке.
- `KD-SET-102` сообщает о повторной загрузке и совпадении/различии байтов.
- Идентичные по байтам повторные PDF предварительно дедуплицируются для
  инженерной сверки, поэтому не вызывают `KD-SET-103`.
- Одиночные документы и случаи отсутствия пары обрабатываются как раньше
  (`KD-SET-101` применяется только для смешанного набора).
- История, статусы инженера, SQLite, Excel и CSV не меняют структуру.

## Границы применимости

Различие байтов может объясняться только метаданными PDF и само по себе
**не устанавливает отличие редакции или инженерного содержания**. Правило
сознательно предпочитает пропустить потенциально вводящую в заблуждение
сверку, чем выбрать файл автоматически. Ключ берётся из существующего
`pair_key()` по имени; основная надпись, ревизии и принадлежность
комплекту пока не исследуются. Документы и хеши не сохраняются данным правилом.

Тесты используют исключительно искусственные PDF и тестовые имена.
