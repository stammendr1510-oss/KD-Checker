# KD-PE-105: позиционные обозначения Э3, отсутствующие в ПЭ3

## Область и код

`KD-PE-105` — предупреждение или информационное замечание о позиционных обозначениях, которые найдены в тексте Э3, но не подтверждены раскрытыми обозначениями ПЭ3.

Правило дополняет `KD-PE-100`–`KD-PE-104`, а не заменяет их:

- `KD-PE-100` — текстовая сверка;
- `KD-PE-101` — обозначения ПЭ3 без текстового подтверждения в Э3;
- `KD-PE-102` — расхождение количества и числа раскрытых обозначений;
- `KD-PE-103` — смешение латинских/кириллических двойников;
- `KD-PE-104` — повтор обозначения в строках ПЭ3;
- `KD-PE-105` — конкретные обозначения Э3, отсутствующие в ПЭ3.

Структурированные доказательства описаны в [`docs/e3-pe3-details-schema.md`](e3-pe3-details-schema.md).

## Алгоритм

1. [`kd_crosscheck.run()`](../kd_crosscheck.py:390) обходит не более 100 страниц Э3.
2. Для каждой страницы один раз извлекаются слова с координатами.
3. Новый модуль нормализует слова и ищет обозначения существующим `TAG`.
4. Контекст классифицируется:
   - `label` — отдельное обозначение;
   - `split_label` — обозначение, восстановленное из переноса строк;
   - `reference` — `3TA2:И1`, строка соединений;
   - `note` — примечание или ссылка на документ;
   - `table` — диапазонная/табличная запись;
   - `unknown` — недостаточно контекста.
5. Повторные упоминания объединяются по нормализованному обозначению.
6. Для суффиксов `.N` (`XT1.1`, `1SF1.8`) сравнение идёт по базовому устройству (`XT1`, `1SF1`).
7. ПЭ3 разбирается существующим [`get_spec_rows()`](../kd_crosscheck.py:193), без повторного разбора:
   - диапазоны `...`, `…`, `;`;
   - переносы строк;
   - несколько групп в одной ячейке;
   - количество;
   - исходная запись;
   - best-effort наименование;
   - признак ограничения 100 страниц.
8. Сравниваются `E3_components` и `PE3_components`.
9. Отсутствующие обозначения привязываются к строке ПЭ3 по семейству и группе.
10. Формируется одно замечание на группу «строка ПЭ3 + набор обозначений».

## Модель достоверности

### Э3

- `high` — есть хотя бы одно `label`;
- `medium` — есть `split_label` или `reference` на двух и более разных листах PDF;
- `low` — одна ссылка, только примечание, только таблица или `unknown`.

`label` — сильное текстовое доказательство, но не доказательство физического наличия. Одна ссылка `3TA2:И1` недостаточна для warning.

### ПЭ3

- `high` — существующий `duplicate_eligible`: полная сетка, границы ячейки, отсутствие `unknown`, точное написание диапазона;
- `medium` — `unknown` пуст, обозначения есть, количество числовое, границы строки известны, строка не выглядит одиночным обозначением при количестве больше 1;
- `low` — остальные случаи.

### Уровень замечания

`warning` только если одновременно:

- достоверность Э3 `high` или `medium`;
- достоверность строки ПЭ3 `high` или `medium`;
- есть уникальная строка-кандидат;
- семейство не клеммное (`X`, `XT`, `XN`, `XL`, `XG`);
- либо `quantity > len(entries)`, либо строка ПЭ3 имеет `high`;
- нет `partial`/`truncated`;
- для `medium`-доказательства Э3 требуется расхождение количества.

Иначе — `info`.

`not_evaluated` — отдельное информационное замечание, если:

- в Э3 нет текстового слоя;
- в ПЭ3 не извлечены обозначения;
- обозначения встречены только в ссылках/примечаниях;
- обработка PDF ограничена.

`error` не используется.

## Контрольный пример

Э3: `1TA1`…`3TA3` — 9 трансформаторов тока.
ПЭ3: `1TA1...1TA3; 2TA1...2TA3; 3TA1`, количество 9.

Ожидается:

- `KD-PE-102` — 9 против 7 раскрытых обозначений;
- `KD-PE-105` — warning с `3TA2` и `3TA3`;
- в `details.missing` — `3TA2`, `3TA3`;
- `details.pe3_quantity = 9`, `details.pe3_entries_count = 7`;
- `details.pe3_name` содержит наименование трансформатора, если оно извлечено;
- `details.e3_pages = [1, 2]`.

При исправленном ПЭ3 (`3TA1...3TA3`) `KD-PE-105` и `KD-PE-102` по группе TA исчезают.

## Ограничения и отказы

- Правило не является OCR и не доказывает физическое отсутствие элемента.
- Скан без текстового слоя даёт `not_evaluated`, а не список отсутствующих.
- Одна ссылка на вывод не даёт warning.
- Примечания, таблицы соответствия и ссылки на другие документы дают только `info`.
- Обозначения, которых нет в тексте Э3, не додумываются по количеству ПЭ3: расхождение количества остаётся `KD-PE-102`, а не превращается в вымышленный список `KD-PE-105`.
- Клеммные семейства на первом этапе не дают warning.
- Если строка ПЭ3 не сопоставлена, вывод только `info`.
- Если PDF обработан не полностью, уровень понижается до `info`.
- Наименование ПЭ3 извлекается best-effort; при неудаче это указывается явно.
- Реальные PDF предприятия в репозиторий не добавляются.

## Совместимость

- Шесть обязательных полей замечания не меняются.
- `details` добавлен только к `KD-PE-105`.
- SQLite-схема не меняется; старые записи читаются без миграции.
- CSV остаётся строго 6-колоночным.
- Excel сохраняет лист `Замечания`; при наличии `details` добавляет колонки K/L.
- История, решения инженера, сравнение проверок и CSV/XLSX работают как раньше.
- Изоляция parser worker и лимиты не ослаблены.

## Ручная приёмка на Windows 11

1. Остановите работающий KD Checker.
2. Распакуйте сборку в новую папку, запустите `start_windows.bat`.
3. Откройте `http://127.0.0.1:8765`.
4. Загрузите синтетические PDF Э3 и ПЭ3 из тестового набора.
5. Убедитесь, что появились `KD-PE-102` и `KD-PE-105`.
6. В `KD-PE-105` проверьте:
   - отсутствуют `3TA2`, `3TA3`;
   - указаны листы Э3 1 и 2;
   - указан лист/строка ПЭ3;
   - указано количество 9 и 7 раскрытых обозначений;
   - есть рекомендация проверить диапазон третьей группы.
7. Назначьте статус, добавьте комментарий, откройте историю.
8. Скачайте Excel: лист `Замечания` содержит `KD-PE-105`, колонки K/L — доказательства и JSON.
9. Скачайте CSV: ровно 6 колонок, человекочитаемое описание и рекомендация.
10. Повторите проверку с исправленным ПЭ3 `3TA1...3TA3`: `KD-PE-105` исчезает.
11. Сравните две проверки: исчезновение замечания не объявляется подтверждённым исправлением.

Если реальные PDF недоступны, этот сценарий остаётся **невыполненным**, а не «пройденным по синтетике».
