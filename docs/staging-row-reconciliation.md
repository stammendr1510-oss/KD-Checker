# Построчная сверка перенесённой истории KD Checker

Эта проверка расширяет офлайн-диагностику PR #76. Она закрывает ситуацию, когда количества строк и внешние ключи правильные, но отдельные значения уже перенесённых запусков, решений или аудита отличаются от исходного архива.

`quality.staging_row_reconciliation.reconcile_staging_rows(staging_path, verified_backup=...)` вызывает базовый `verify_staging_import` и после успешной структурной проверки сверяет **каждую** нормализованную запись с её архивным источником.

## Контракты

- Все legacy run ID присутствуют в scoped runs ровно один раз; совпадают даты, JSON файлов и замечаний, редакция и назначенный org/project.
- `previous_id` соответствует предыдущему запуску с тем же составом файлов, а не произвольному существующему ID.
- Каждое исходное `finding_state` отображается ровно в один `decision` с тем же статусом, комментарием, версией, датой и порядковым номером.
- Каждое исходное событие истории отображается по исходному ID на одну запись `events`; совпадают старые и новые статусы/комментарии, версии, время и привязка к замечанию.
- Автор исторических строк сохранён как `legacy_unknown`, а не ошибочно приписан оператору миграции.
- Сначала проходят структурные проверки PR #76 и, если указана копия, её SHA-256 и полная проверка архива. При их ошибке построчная сверка **не объявляется завершённой**.
- Отчёт содержит только коды ошибок, счётчики и признаки `reconciled/backup_checked`; в нём нет названий организаций, имён документов и комментариев.

## Важные ограничения

При `backup_checked=false` сверяется только взаимная согласованность двух наборов строк **в одном staging**, а не подлинность происхождения. Даже при наличии резервной копии SHA-256 подтверждает соответствие её байтам, но не доказанную подлинность оригинала. Это не цифровая подпись, не механизм миграции PostgreSQL, не переключение рабочей базы и не готовность к двухкомпьютерной эксплуатации.

Оба файла — доверенные остановленные локальные копии; не проверять общие сетевые файлы SQLite в рабочем режиме. Функция не делает изменений в storage или production. При неизвестном формате — fail-closed.

## Синтетические испытания

`python -m pytest -q tests/test_staging_row_reconciliation.py`

В наборе проверяются успешная полная сверка, отсутствие копии, подмена даты, состава файлов, предыдущего запуска, scope, ID аудита, расхождение количества замечаний, подмена исходной архивной строки, повреждение решения и несовпадение резервной копии.

PR основан на #76 (зависит также от #56/#45/#55). Его собственные изменения — новый модуль, тесты и документация. Не объединять до родительских PR и ручного review. Для экономии GitHub Actions нужен один итоговый CI Windows/Linux.
