# Читаемость отчёта и нормализация PDF

В результатах и открытой записи истории используются карточки замечаний вместо
узкой семиколоночной таблицы. В каждой карточке отдельно показаны уровень и код,
полное имя документа, место, описание, рекомендация и решение инженера.
На широком экране редактор решения расположен справа, на узком — под текстом.
Комментарии, кнопки сохранения, журнал и ссылки на Excel/CSV доступны как прежде.
Длинные имена и строки переносятся без обрезания текста и без горизонтального
расширения страницы. Цвет дополняет русскую подпись уровня, а не заменяет её.

Уровни в интерфейсе и Excel: «Ошибка», «Предупреждение», «Информация».
Машинные `error`, `warning`, `info`, ключи счётчиков API и существующий CSV
сохраняются. Excel уже использовал русские названия; его формат не меняется.

## Границы нормализации

Общий читатель `extractors.py` не склеивает текст: порядок страниц, блоков и
колонок PDF нельзя безопасно восстановить глобальным удалением переносов.
Изменения ограничены разбором позиционных обозначений в `kd_crosscheck.py`.

- В ПЭ3 используются прежние координаты ячейки, границы таблицы и текстовые блоки.
  Фрагменты неполного обозначения (`1K` + `M1`, `XT` + `12`) и явно заданного
  диапазона (`1KM1` + `...1KM3`) могут соединяться. Разделитель `;` сохраняется.
- Завершённое обозначение или диапазон не дополняется следующим числом/именем:
  `XT1` + `2` не превращается в `XT12`, а `1KM1...1KM3` + `4` не расширяется
  до `1KM34`. Такой фрагмент остаётся в списке `unknown` с исходными пробелами
  и переносами. Это ограничение касается также отдельных слов одной PDF-строки.
- В Э3 дополнительно восстанавливаются только два односоставных слова на двух
  близких строках одного текстового блока, выровненных по левому краю. Первое
  слово должно быть неполным буквенным префиксом, второе — его продолжением
  с явно присутствующим номером; соединение должно точно соответствовать
  поддерживаемому синтаксису обозначения. Между словами не должно быть линии
  таблицы. Разные блоки, страницы, колонки и блоки с тремя строками не соединяются.

Это консервативные условия для известных текстовых PDF, а не универсальный
анализ графики. Текстовые блоки зависят от экспортера. Сканированные PDF без
текста, необычная вёрстка, другие алфавиты и неподдерживаемые префиксы могут
потребовать ручной сверки. Номера не выводятся из количества элементов, соседних
строк, отсутствующих концов диапазонов или наличия обозначений в парном документе.
Неоднозначный фрагмент не является доказательством точного числа обозначений.

KD-PE-102 остаётся предупреждением для явно распознанных 7 обозначений при
количестве 9. Регрессионный искусственный комплект также сохраняет 64 уникальных
обозначения ПЭ3 и 64 совпадения, даже если Э3 содержит ещё два обозначения.
Это проверка заданного сценария на синтетических PDF, а не новая проверка
документации предприятия. Исходные PDF и сохранённые результаты старых проверок
не переписываются.

## Совместимость и проверка

Схема SQLite, статусы, комментарии, журнал и правила идентификации не изменены.
**Новая миграция не требуется**, если версия с PR №5 уже установлена. Для более
старой версии по-прежнему применима [инструкция PR №5](issue-management.md).
Новые результаты с фактически исправленным распознаванием могут содержать
другой текст/состав обозначений; существующее консервативное сопоставление не
обещает связать изменённый результат и не переносит статус автоматически.

Все тестовые PDF создаются программно. Браузерные тесты проверяют подписи,
длинные строки, ширины 360/768/1366/1920, сохранение решений после перезагрузки,
журнал, неизменность API/CSV и содержимое Excel. Полный набор выполняется
существующим GitHub Actions на Windows и Linux.
