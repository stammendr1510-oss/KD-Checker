# Независимая отрицательная приёмка JSON API соединений

Набор поверх Codex PR #65, с обязательными родительскими зависимостями #44/#52/#55/#59/#60 и #46/#47/#57. **Ветка Codex #65 и его runtime не изменены.**

Синтетические HTTP-тесты с реальным `ScopedBackend`, проверкой ролей/проектов и временной SQLite:

- отклонение не-объектных, неполных и повреждённых JSON, duplicate object keys, NaN и Infinity;
- отклонение чужого проекта, некорректной топологии записи и неверных типов;
- явный отказ для Content-Type не JSON и тела свыше 512 КиБ;
- контроль отсутствия частично созданных runs/decisions/events после отказов;
- успешная информационная проверка повторной явной записи KD-CON-101 с сохранением истории;
- запрет чтения и экспорта соединений из чужой организации.

Тесты **не подтверждают достоверность электрических соединений** и не являются поддержкой native EPLAN. Поля JSON — лишь утверждения источника, никакие реальные данные предприятия не используются.

## Команда

`python -m pytest -q tests/test_connection_api_adversarial.py`

Затем полный CI Windows/Linux и совместный прогон с принятыми исходными PR. Временная целевая ветка `main` позволяет штатный CI, но её diff содержит родителей; не объединять раньше зависимостей и ручного review.
