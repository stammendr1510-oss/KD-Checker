# Проверка КД — самостоятельное веб-приложение (MVP 0.1)

## Архитектура

Браузер → FastAPI (`app.py`) → читатели форматов (`extractors.py`) → детерминированные правила (`engine.py`) → SQLite (`storage.py`) → отчёт CSV.

Код и настройки локальные, нет запросов к ChatGPT или облачным AI. Сами документы не сохраняются в базе; сохраняются имена файлов и выявленные замечания.

## Запуск на Windows

1. Установить Python 3.11+ с сайта python.org (включить «Add Python to PATH»).
2. Распаковать архив в папку без ограничений записи.
3. Дважды нажать `start_windows.bat` (при первом запуске требуется интернет для установки Python-библиотек).
4. Открыть http://127.0.0.1:8765 — в большинстве случаев вкладка откроется автоматически.
5. Для остановки закрыть окно консоли или нажать Ctrl+C.

Альтернативный запуск (Linux/macOS/Windows): `python -m venv .venv`, установить `pip install -r requirements.txt`, выполнить `python app.py`.

## Реально реализованные проверки

- **KD-000**: невалидный/неподдерживаемый файл.
- **KD-001**: обозначение в имени по настраиваемому шаблону.
- **KD-002**: отсутствие достаточного текстового слоя PDF (без OCR).
- **KD-003**: пустой modelspace DXF.
- **KD-004**: информационная отметка о невозможности глубокого анализа DWG.
- **KD-005**: ограничение на число страниц PDF и листов Excel.
- **KD-010**: отсутствие столбцов спецификации в XLSX/XLSM/CSV.
- **KD-011**: повтор позиции на листе спецификации.
- **KD-012**: эвристическая сверка обозначения в спецификации с именами приложенных файлов; допускает ложные срабатывания.
- **KD-020**: совпадающее обозначение в одинаковом формате.

Это **проверки-эвристики**, а не сертификация ЕСКД/ГОСТ. Правила можно включать/выключать в разделе «Правила». Обозначения/форматы требуют настройки под вашу систему КД. Макросы XLSM не исполняются.

## Ограничения и безопасность

- Поддерживаются PDF, XLSX, XLSM, CSV, DXF, DWG (для DWG — только регистрация/уведомление, без чтения геометрии).
- Лимиты: 100 файлов, 20 МБ на файл, 100 МБ за запрос; PDF — 100 страниц, Excel — 30 листов, 5000 строк × 40 столбцов на лист.
- Не реализованы OCR, автоматическое чтение размеров чертежа, полноценная проверка ЕСКД/ГОСТ, прямой анализ DWG, EPLAN native data, роли пользователей и разграничение прав.
- По умолчанию веб-сервер доступен **только на данном компьютере** (`127.0.0.1`). **Не открывайте его в интернет:** в MVP нет авторизации, CSRF-защиты и защищённой инфраструктуры. Для общего доступа нужны reverse proxy, TLS, авторизация, лимиты сервера и резервное копирование.
- Настройки лежат в `config.json`; история — в `data/history.sqlite3`. Делайте резервные копии этих файлов.
- Для эксплуатации на недоверенных документах следует усилить изоляцию обработки, лимиты на распаковку/CPU и вести контроль зависимостей.

## Тесты

`pip install -r requirements.txt -r requirements-dev.txt`, затем
`python -m playwright install --with-deps chromium` и `python -m pytest -q`.
Полный набор включает браузерный сценарий на искусственных данных.

## Экспорт отчётов

Кнопка «Скачать отчёт Excel» сохраняет проверку в `.xlsx`: лист «Общие сведения»
содержит сохранённую дату проверки (UTC), файлы и число замечаний каждого уровня;
лист «Замечания» — нумерованный перечень с фильтрами, закреплённым заголовком,
переносом текста и цветами уровней. Отчёт доступен сразу после проверки,
в списке истории и при открытии сохранённой проверки.

Существующий CSV доступен рядом с Excel. Оба формата строятся локально из истории,
без ChatGPT и повторной обработки исходных документов. В XLSX текстовые поля
записываются строками, включая значения с `=`, `+`, `-`, `@`; они не исполняются
как формулы. Переносы CRLF приводятся к LF, недопустимые управляющие символы XML
удаляются. Дополнительные зависимости для Excel не нужны: используется `openpyxl`.

Адрес скачивания Excel: `GET /api/runs/{run_id}/xlsx`.

## Расширение

Модули проверок добавлять в `engine.py`, читатели новых типов в `extractors.py`, веб-маршруты в `app.py`. Следующий шаг — классификатор документов, проверка основной надписи, связи ЕСКД и пакетный импорт архивов с ограничениями распаковки.

## Новое в версии 0.2 — экспериментальная сверка Э3 ↔ ПЭ3

При совместной загрузке двух PDF одного комплекта (имена содержат `.Э3` и `.ПЭ3`)
программа пытается извлечь обозначения из схемы и строк перечня элементов,
раскрывает однозначные диапазоны (`1KM1...1KM8`) и добавляет информационные
результаты с кодами `KD-PE-100`, `KD-PE-101`, `KD-PE-102`.

**Ограничения:** сопоставление только текстового слоя PDF; не анализирует
электрическую топологию, не доказывает правильность соединений и не заменяет
сверку по структурированным экспортам EPLAN. Количество клемм внутри одной
колодки — не количество обозначений колодок, поэтому не считается ошибкой.
Неоднозначные или переносимые обозначения отмечаются как информация,
а не подтверждённая ошибка. Исходные документы на сервере не сохраняются.
Для многопользовательского доступа MVP пока не предназначен: локальный адрес
127.0.0.1 и отсутствие авторизации являются осознанными ограничениями.

Для обновления Windows: остановите старый сервер (Ctrl+C), распакуйте архив
в **новую папку**, запустите `start_windows.bat`. История и настройки из
старой установки не переносятся автоматически. Не заменяйте работающие файлы
поверх старой установки.



## Управление замечаниями

Для замечаний доступны статусы «Новое», «В работе», «Устранено» и «Отклонено с
обоснованием», комментарий инженера и журнал изменений. Решения сохраняются
отдельно от результатов проверок и отображаются также в Excel. При повторной
проверке статус не переносится: прошлое решение показано для инженерной сверки.

Перед обновлением остановите сервер. [Инструкция по миграции, резервированию,
откату и ограничениям сопоставления](docs/issue-management.md).

## Отображение результатов и PDF

Результаты и история показывают карточки с русскими уровнями, полным именем
документа и доступным редактором решения инженера. Карточки адаптируются к ширине
экрана. [Условия восстановления обозначений PDF и ограничения](docs/report-usability.md).
После версии с управлением замечаниями дополнительная миграция SQLite не нужна.

## Повторы обозначений ПЭ3

`KD-PE-104` предупреждает о распознанных повторах обозначения в разных строках
одного ПЭ3, включая разные страницы и пересечения диапазонов. Проверка не требует
парного Э3. Неоднозначные записи и строки без достоверных границ пропускаются;
повтор требует проверки инженером и не считается подтверждённой ошибкой КД.
[Условия проверки, исключения и ограничения](docs/pe3-duplicates.md).
Изменение схемы SQLite не требуется.

## Контроль наличия парных Э3 и ПЭ3 в загрузке

`KD-SET-101` — информационное сообщение о том, что для Э3 или ПЭ3 не обнаружен парный PDF среди **загруженных файлов**, когда в одной проверке уже представлены оба типа документов. Одиночная проверка одного типа не вызывает такое сообщение. Это не утверждение о неполноте самой конструкторской документации. [Условия и ограничения](docs/document-pair-presence.md).

## Повторные PDF в одном загруженном наборе

`KD-SET-102` — информационное замечание, когда несколько PDF имеют одинаковый тип Э3/ПЭ3 и одинаковый ключ обозначения. Во время загрузки сравниваются байты: одинаковое содержимое отличается от разных PDF-версий, но оба случая требуют ручной сверки и не доказывают нарушение КД. [Описание и ограничения](docs/document-pdf-collisions.md).

## Неоднозначные редакции парных PDF

`KD-SET-103` — информационное замечание: если для одного обозначения загружены разные по байтам Э3 или ПЭ3, автоматическая сверка этой пары пропускается, чтобы не смешивать потенциальные версии. Другие пары и самостоятельные проверки ПЭ3 продолжают работать. [Условия и ограничения](docs/ambiguous-pdf-pairs.md).

## Сравнение проверок «до / после» (API)

`GET /api/runs/{current_id}/compare/{previous_id}` сопоставляет результаты двух проверок того же набора файлов: новые, сохраняющиеся, исчезнувшие и неоднозначные замечания. Появление и исчезновение записи не подтверждают изменение конструкции; решения инженера не переносятся. [Условия и пример ответа](docs/run-comparison.md). Экран сравнения доступен в разделе «История»: откройте текущий запуск и укажите номер предыдущей проверки.


## Уточнение места замечания о количестве ПЭ3

Информационная подсказка к предупреждению `KD-PE-102` теперь показывает
«Лист PDF N, строка таблицы M», **только если строка подтверждена
горизонтальными границами таблицы в PDF**. Без достоверной сетки остаётся
«Лист PDF N», без вымышленного номера строки. Это дополнительная
навигация для инженера, а не автоматическое признание несоответствия КД.

## Подтверждённые текстовые совпадения Э3 ↔ ПЭ3

Информационное `KD-PE-100` помимо количества совпадений показывает
не более пяти примеров обозначений и номера страниц PDF Э3, на которых они
встречаются в извлечённом тексте. Для одного обозначения показываются первые
три страницы и количество остальных страниц. Повторения в пределах страницы
не дублируются. Это помогает инженеру перейти к источнику, но не подтверждает
согласованность графики, полноту схемы или отсутствие ошибки в КД.
Для отсутствующих текстовых совпадений страницы не выдумываются.

## Полный набор PDF из EPLAN

Независимый модуль учитывает явно обозначенные ВО/Э3/ПЭ3/СП в текущей загрузке.
KD-SET-201/202 показывают информационную сводку и повторные типы/ключи; KD-SET-203
ссылается только на достоверную строку СП с документом, не включённым в загрузку.
Это не подтверждение полноты или отсутствия КД в выпуске. Прежние проверки пар
и EPLAN Checklist не изменены. [Область, синтаксис имён, ограничения СП и дизайн
проверки листности](docs/full-set-completeness.md). Миграция SQLite не нужна.
