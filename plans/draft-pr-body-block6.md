## Назначение

Финальная регрессия KD-PE-105 (блок 6) и подготовка кандидата для независимой
инженерной приёмки на Windows 11.

- База: `feature/e3-pe3-missing-designations` @ `a968ef8d533281369dfecdc99df6615cba771e24`.
- Ветка: `feature/kd-pe-105-acceptance`.
- Интеграционный коммит блоков 3–5: `82ea32828a6c72d2bccd0bbeaa9b17bb1fd13d47`.
- `main`, Supabase, EPLAN Checklist и production не изменяются.
- Merge не выполняется. Реальные PDF/XLSX не добавляются.

## Что входит

Блоки 1–5 в одном stacked diff:

1. диагностическая база и синтетические воспроизведения;
2. доказательное сопоставление обозначений Э3 со строками ПЭ3;
3. контекстная классификация изделий, контактов, ссылок и неоднозначных токенов;
4. централизованная модель достоверности (правило минимума, без числовых весов);
5. представление доказательств для инженера в API, UI, Excel и защищённом
   рабочем месте.

Блок 6 добавляет отчёт о регрессии, матрицу «до/после» и инструкцию для
Windows 11.

## Контрольный сценарий TA

```text
severity=warning reason=quantity_mismatch confidence=high
missing=['3TA2', '3TA3']
pe3_page=2 pe3_table_row=2 pe3_quantity=9 pe3_entries_count=7
```

`3TA2` и `3TA3` обнаруживаются, количество 9 не порождает обозначений,
строка ПЭ3 подтверждена, `valid_details() == True`.

## Совместимость

- Схема `details` v1 не расширялась.
- CSV — строго 6 колонок; Excel — 10 колонок, 12 при наличии `details`.
- SQLite, история решений и fingerprint не мигрируются.
- `KD-PE-100`–`KD-PE-104` не заменяются.
- Изоляция parser worker и лимиты не ослаблены.

## Ограничения

1. Реальные Э3/ПЭ3 и XLSX недоступны; приёмка на реальных документах не
   выполнена.
2. Windows 11 не запускался; `950 passed, 5 skipped` из постановки не
   воспроизводимы. Linux: `1080 passed, 1 skipped`.
3. KD-PE-105 — текстовое сопоставление, не OCR и не доказательство
   физического отсутствия элемента.
4. Одиночный `X1` классифицируется как неоднозначный, но при `kind=label`
   остаётся info-кандидатом `no_matching_pe3_row`; warning невозможен.
   Ограничение зафиксировано для решения по блоку 7.
5. GitHub Actions реагирует только на PR в `main`, поэтому stacked PR его не
   запускает; прямой GitHub push недоступен без токена. Публикация выполнена
   Draft PR в SourceCraft.
