# KD-PE-111: протокол независимой инженерной приёмки

Ветка: `feat/kd-pe-111-independent-acceptance` (база `feat/kd-pe-110-electrical-graph`, `a24d6c9`).
Состав: `tests/test_independent_acceptance.py` (20 тестов), только новые файлы; `main`,
`config.json`, `connection_checks.py` не изменялись.

## Принцип holdout / «слепой» приёмки

Все сценарии построены на полностью незнакомых синтетических классах
(`VR`, `BL`, `GX`, `NK` через `configure_reference_classes`), незнакомых именах
документов (`Э3-ГХ-7701`, `ПЭ3-ГХ-7701`, `СП-ГХ-7701`, `ВО-ГХ-7701`, проект
`ГХ.7710.7701`) и шкафах `ШЗА-77`. Классы `TA/QF/KM/KLD/SO/ZZ/MQ/PT` и
имена из существующих тестов не используются. Внешние API и реальные CAD-файлы
не задействованы; много документные сценарии (Э3 + ПЭ3 + СП + ВО) собираются
в памяти через PyMuPDF.

## Проверенная матрица правил

| Код | Сценарий приёмки | Проверено |
|---|---|---|
| KD-EM-108-1 | Расхождение количества и числа обозначений в строке ПЭ3; точный код, severity, provenance (лист/строка) | да |
| KD-EM-108-2 | Документ из СП отсутствует в загрузке; ссылка на СП как источник | да |
| KD-EM-108-3 | Смешение кириллицы/латиницы (латинская `B` vs кириллическая `В`); обе исходные формы и места в сообщении | да |
| KD-EM-109-1 | Конфликт клеммы: один `(устройство, клемма)` в разных проводах; повтор в том же проводе — ложное срабатывание отсутствует | да |
| KD-EM-109-2 | Полнота Э3↔ПЭ3 в обе стороны (info, не ошибка КД) | да |
| KD-EM-109-3 | Нераспознанные фрагменты строки при количестве > подтверждённого; фрагменты без расхождения молчат | да |
| KD-EM-110-1 | «Висящее» устройство без единого соединения; при пустом экспорте соединений вердикт не выносится | да |
| KD-EM-110-2 | Кольцо провода через 3+ контакта; двухузловой повторный экспорт кольцом не считается | да |
| KD-EM-110-3 | Число различных проводов кабеля vs количество в ПЭ3; строки с метражем (м/мм/км) пропускаются | да |

Чистый комплект holdout (согласованные Э3/ПЭ3/СП/ВО + структурные соединения)
даёт ноль ложных срабатываний по всем правилам; граф детерминирован
(сортированные узлы и соседи).

## Сквозной шов (adapters.engineering_findings)

- Чистый holdout-комплект из реально собранных в памяти PDF → `[]`.
- Дефектный комплект (рассинхрон количества ×2, ссылка СП на отсутствующий
  документ, непокрытие Э3↔ПЭ3 в обе стороны, нераспознанный фрагмент) → ровно
  ожидаемые коды `KD-EM-108-1/108-2/109-2/109-3` с корректными файлами-источниками.
- Правила `KD-EM-110-*` без структурных соединений корректно молчат.

## Граница «извлечение vs инженерия»

Сырой шум извлечения (нераспознанные фрагменты, пустые и невалидные строки)
поверхностно обрабатывается: сценарий `KD-EM-109-3` не падает, не искажает
граф (пустой `build_graph`), не порождает лишних кодов. Электрическая
tопология никогда не выводится из текста PDF — только из валидированных
`Connection`-записей.

## Зависимости извлечения

`kd_crosscheck.get_spec_rows` (табличная геометрия ПЭ3: колонка обозначений,
заголовок «кол», горизонтальные линейки), `kd_crosscheck.scheme_designations`
(теги + склейка перенесённых подписей), `full_set_completeness.specification_references`
(явные ячейки «обозначение» в штрихованной сетке), `classify_pdf_name`
(строгая классификация имён файлов).

## Честные границы системы

- Смешение алфавитов (`KD-EM-108-3`) через PDF-извлечение недостижимо:
  тег-регулярки латинские; сценарий проверен на уровне модели.
- Синтетические PDF собраны под геометрические ожидания экстракторов; это
  проверка шва, а не сертификация парсинга произвольных сканов.
- Все находки — warning/info с явной оговоркой «не подтверждённая ошибка КД»;
  финальный вердикт остаётся за инженером.
- Полный матричный прогон (955+ тестов) выполняется в GitHub Actions.
