# KD-PE-113 — Универсальная семантическая модель строк ПЭ3 и совместимость с Windows 11

## Назначение

Классификация строк перечня элементов (ПЭ3) по смыслу записи: устройство,
принадлежность, элемент сборки, групповая позиция или неоднозначная запись.
Цель — устранить ложные срабатывания правил количества и полноты
(KD-EM-108-1, KD-EM-109-2/3, KD-PE-102/105) на строках, где количество
измеряет не число устройств, при сохранении настоящих ошибок количества.

## Семантический дескриптор строки (`SpecRow`)

Поля (заполняет `adapters._classify_spec_row`, источник — уже извлечённые
данные `kd_crosscheck.get_spec_rows`):

- `row_role` — `standalone_device` | `accessory` | `assembly_element` |
  `grouped_position` | `ambiguous`;
- `parent_ref` — нормализованное обозначение родительского устройства
  (общая буквенная основа с предыдущей строкой) или `None`;
- `quantity_semantics` — `device_count` | `accessory_qty` |
  `assembly_units` | `grouped_instances` | `length_or_bulk`;
- `classification_confidence` — `confirmed` | `ambiguous`;
- `provenance` — существующий `SourceRef` (документ, лист, строка, границы).

## Правила классификации (многофакторные)

Никакой фактор не решает в одиночку; запрещены правила по конкретным кодам
устройств, именам файлов и номерам листов.

1. **Нераспознанные фрагменты + отсутствие геометрии таблицы** → `ambiguous`.
2. **Пустая ячейка обозначения** (или отступ) сразу после строки устройства
   с подтверждённой сеткой таблицы **и** описанием типа «комплект / крепёж /
   принадлежность» → `accessory`, `parent_ref` = предшествующее
   устройство. Пустая ячейка без описательных признаков недостаточна.
3. **Отступ + собственное обозначение + общий родитель** →
   `assembly_element` (`assembly_units`).
4. **Единицы длины/массы в наименовании** (м, мм², кг, пог. м…) без сетки →
   `assembly_element` (`length_or_bulk`).
5. **Несколько раскрытых обозначений** → `grouped_position`.
6. **Подтверждённая сеткой строка с одним обозначением**, без единиц длины и
   без признаков принадлежности → `standalone_device` (`device_count`).
   Количество больше 1 здесь — настоящее несоответствие и **сохраняется**
   для KD-EM-108-1.
7. Иначе → `ambiguous`.

## Влияние на правила проверки

- **KD-EM-108-1**: срабатывает только при `row_role` ∈ {`standalone_device`,
  `grouped_position`} и `quantity_semantics` ∈ {`device_count`,
  `grouped_instances`}. Строки `accessory`, `assembly_element`,
  `length_or_bulk` не порождают предупреждение о количестве.
- **KD-EM-109-3**: подтверждённые строки устройств с нераскрытыми фрагментами
  исключаются (они уже учтены как несоответствие количества); неподтверждённые
  строки по-прежнему сообщаются как «необходима ручная проверка».
- **KD-EM-109-2**: обозначения строк `accessory` и `assembly_element`, а
  также строк `length_or_bulk`, исключены из множества устройств ПЭ3 — они
  описывают материалы под родительским устройством, а не самостоятельные
  устройства схемы.
- **KD-PE-102** (legacy): групповые строки без сетки таблицы или с единицами
  длины/массы в наименовании больше не порождают предупреждение.
- **KD-PE-105**: строка с единицами длины/массы не может служить доказательством
  «недораскрытого диапазона» (MATCH_UNDER_EXPANDED).
- **KD-EM-112-1/112-2**: не изменены; работают по всем строкам независимо от
  роли (конфликты атрибутов и визуально похожие токены моделей).

## Совместимость с Windows 11

`tests/test_independent_acceptance.py`: жёсткий путь Linux-шрифта заменён на
`_cyrillic_font()` — поиск по `C:\Windows\Fonts` (Consolas/Courier/Arial),
затем типовые каталоги Linux, затем рекурсивный поиск TTF; при полном
отсутствии кириллического шрифта тест пропускается с явной причиной.

## Границы решения

- Классификация опирается только на извлечённый текст и геометрию таблицы;
  OCR-сканы без текстового слоя охватываются существующими диагностиками.
- `engineering_flags.json` и зафиксированная схема `config.json` не менялись.
- Проверка `tools/dependency_policy.py` пройдена; новых зависимостей нет.
